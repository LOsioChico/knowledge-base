> Last-chance handlers when something throws in [[nestjs/fundamentals/guards|guards]], [[nestjs/fundamentals/interceptors|interceptors]], [[nestjs/fundamentals/pipes|pipes]], the controller, or service code reached from that request path. Filters run **only on failure inside Nest's exception zone**.

## Default behavior

Nest ships a global filter:

- `HttpException` (and subclasses) → that exception's `status` + response body:
  ```http
  // Request:
  GET /todos/9999

  // Response:
  HTTP/1.1 404 Not Found
  Content-Type: application/json; charset=utf-8

  {
    "statusCode": 404,
    "message": "Cannot GET /todos/9999",
    "error": "Not Found"
  }
  ```
- Anything else → `500` with `{ "statusCode": 500, "message": "Internal server error" }`:
  ```http
  // Request:
  GET /todos

  // Response:
  HTTP/1.1 500 Internal Server Error
  Content-Type: application/json; charset=utf-8

  {
    "statusCode": 500,
    "message": "Internal server error"
  }
  ```

Write a custom filter when you need a stable JSON shape, domain-error mapping, or logging to Sentry/Datadog.

<Aside type="caution" title="Filters do not catch middleware errors">

[[nestjs/fundamentals/middleware|Middleware]] runs before Nest's exception zone. If middleware throws or calls `next(err)`, the platform handler deals with it: not your `@Catch()` filters. Keep route authorization, DTO validation, and handler response shaping inside Nest layers when you want filter behavior.

</Aside>

## What filters catch vs what they do not

<Tabs>
  <TabItem label="Inside Nest">
    Controller or service throws with a custom filter registered:

    ```typescript
    import { Controller, Get, Param, UseFilters, ExceptionFilter, Catch, ArgumentsHost, HttpStatus } from "@nestjs/common";
    import { Response } from "express";

    // Standalone mock to ensure complete copy-pasteability
    export class UserNotFoundError extends Error {
      constructor(public readonly id: string) {
        super(`User ${id} not found`);
      }
    }

    @Catch(UserNotFoundError)
    export class UserNotFoundFilter implements ExceptionFilter<UserNotFoundError> {
      catch(exception: UserNotFoundError, host: ArgumentsHost): void {
        const response = host.switchToHttp().getResponse<Response>();
        response.status(HttpStatus.NOT_FOUND).json({
          error: "USER_NOT_FOUND",
          userId: exception.id,
        });
      }
    }

    @Controller("users")
    @UseFilters(UserNotFoundFilter)
    export class UsersController {
      @Get(":id")
      findOne(@Param("id") id: string) {
        throw new UserNotFoundError(id);
      }
    }
    ```

    Request:

    ```bash
    curl -i http://localhost:3000/users/missing-id
    ```

    Response:

    ```json
    {
      "error": "USER_NOT_FOUND",
      "userId": "missing-id"
    }
    ```

    This is the normal filter path: the exception bubbles through Nest, the filter matches, and the filter owns the HTTP body.

  </TabItem>
  <TabItem label="Outside Nest">
    Middleware throws before Nest reaches guards, pipes, or the controller:

    ```typescript
    import { INestApplication } from "@nestjs/common";

    declare const app: INestApplication;

    app.use("/webhooks", (_req, _res, next) => {
      next(new Error("bad signature"));
    });
    ```

    Request:

    ```bash
    curl -i http://localhost:3000/webhooks
    ```

    Observable result:

    ```http
    HTTP/1.1 500 Internal Server Error
    Content-Type: text/html; charset=utf-8
    Content-Length: 139

    <!DOCTYPE html>
    <html lang="en">
    <head>
    <meta charset="utf-8">
    <title>Error</title>
    </head>
    <body>
    <pre>Error: bad signature</pre>
    </body>
    </html>
    ```

    Notice that your custom Nest filter does not run; the response shape comes directly from the underlying HTTP adapter (Express/Fastify) error handling instead of Nest's exception zone.

    That is the boundary: middleware failures do not pass through `@Catch()`.

  </TabItem>
</Tabs>

## Contract

```typescript title="http-exception.filter.ts"
import { ArgumentsHost, Catch, ExceptionFilter, HttpException } from "@nestjs/common";
import { Request, Response } from "express";

@Catch(HttpException)
export class HttpExceptionFilter implements ExceptionFilter<HttpException> {
  catch(exception: HttpException, host: ArgumentsHost): void {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();

    response.status(exception.getStatus()).json({
      statusCode: exception.getStatus(),
      timestamp: new Date().toISOString(),
      path: request.url,
      message: exception.message,
    });
  }
}
```

`@Catch(A, B)` registers types; `@Catch()` with **no args** is catch-all.

<Aside type="caution" title="Prefer the class when the filter needs DI">

`@UseFilters(HttpExceptionFilter)` lets Nest reuse the filter and inject dependencies. `@UseFilters(new HttpExceptionFilter())` is valid for dependency-free filters, but it skips DI. Same rule as [[nestjs/fundamentals/guards|guards]].

</Aside>

## Resolution order (inverted)

Every other layer: **global → controller → route**. Filters: **route → controller → global**. First `@Catch()` match wins: siblings do not chain.

<Steps>

1. Exception bubbles out of handler / pipe / guard / interceptor inside Nest's exception zone.
2. Nest builds the filter list for that route and **reverses** metadata so route filters are tried first.
3. **One** filter handles it; no second filter at the same scope runs.
4. To "always log, then format", extend `BaseExceptionFilter` and call `super.catch()`.

</Steps>

    `@UseFilters` array is **reversed** before search. Put catch-all **first** in the decorator so typed filters win:

    ```typescript
    import { Controller, Get, UseFilters, ExceptionFilter, Catch, HttpException } from "@nestjs/common";

    // Dummy filters for compiler/import completeness
    @Catch() export class CatchEverythingFilter implements ExceptionFilter { catch() {} }
    @Catch(HttpException) export class HttpExceptionFilter implements ExceptionFilter { catch() {} }

    @Controller("cats")
    @UseFilters(CatchEverythingFilter, HttpExceptionFilter) // Catch-all first in source → HttpExceptionFilter checked before catch-all
    export class CatsController {
      @Get()
      findAll() {}
    }
    ```

    ```http
    // Correct Order HTTP outcomes:

    // 1. Throwing NotFoundException (HttpExceptionFilter wins and runs):
    GET /cats
    → HTTP/1.1 404 Not Found
    { "statusCode": 404, "message": "Not Found" }

    // 2. Throwing generic Error (CatchEverythingFilter wins and runs):
    GET /cats
    → HTTP/1.1 500 Internal Server Error
    { "statusCode": 500, "message": "Internal server error" }
    ```


    ```http
    GET /cats
    ```

<Aside type="caution" title="Throwing inside a filter">

Sibling filters do not chain. If your `catch()` method throws, the filter that already matched is the one that failed. Prefer `super.catch(exception, host)` when extending `BaseExceptionFilter` instead of rethrowing from a custom filter.

</Aside>

## Built-in HTTP exceptions

| Class                          | Status |
| ------------------------------ | ------ |
| [BadRequestException](#with-validationpipe)          | 400    |
| `UnauthorizedException`        | 401    |
| `ForbiddenException`           | 403    |
| [NotFoundException](#catch-all-ordering)            | 404    |
| `ConflictException`            | 409    |
| [InternalServerErrorException](#catch-all-ordering) | 500    |

Throw these from services/controllers; filters map domain errors when you want stable `error` codes.

## Recipes

### Domain error → HTTP

```typescript title="user-not-found.error.ts"
export class UserNotFoundError extends Error {
  constructor(public readonly id: string) {
    super(`User ${id} not found`);
  }
}
```

```typescript title="user-not-found.filter.ts"
import { ArgumentsHost, Catch, ExceptionFilter, HttpStatus } from "@nestjs/common";
import { Response } from "express";
import { UserNotFoundError } from "./user-not-found.error";

@Catch(UserNotFoundError)
export class UserNotFoundFilter implements ExceptionFilter<UserNotFoundError> {
  catch(exception: UserNotFoundError, host: ArgumentsHost): void {
    const response = host.switchToHttp().getResponse<Response>();
    response.status(HttpStatus.NOT_FOUND).json({
      error: "USER_NOT_FOUND",
      userId: exception.id,
    });
  }
}
```

Register the filter on your controller or route handler:

```typescript title="users.controller.ts"
import { Controller, Get, Param, UseFilters } from "@nestjs/common";
import { UserNotFoundError } from "./user-not-found.error";
import { UserNotFoundFilter } from "./user-not-found.filter";

@Controller("users")
export class UsersController {
  @Get(":id")
  @UseFilters(UserNotFoundFilter)
  findOne(@Param("id") id: string) {
    throw new UserNotFoundError(id);
  }
}
```

* **HTTP exchange**:
  ```json
  GET /users/missing-id

  → 404 Not Found
  {
    "error": "USER_NOT_FOUND",
    "userId": "missing-id"
  }
  ```

### Platform-agnostic catch-all

Use `HttpAdapterHost` instead of accessing the platform-specific response object directly so the same filter works seamlessly on both Express and Fastify ([HTTP adapter](https://docs.nestjs.com/faq/http-adapter)).

```typescript title="all-exceptions.filter.ts"
import { ArgumentsHost, Catch, ExceptionFilter, HttpException, HttpStatus } from "@nestjs/common";
import { HttpAdapterHost } from "@nestjs/core";

@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  constructor(private readonly httpAdapterHost: HttpAdapterHost) {}

  catch(exception: unknown, host: ArgumentsHost): void {
    const { httpAdapter } = this.httpAdapterHost;
    const ctx = host.switchToHttp();

    const httpStatus =
      exception instanceof HttpException
        ? exception.getStatus()
        : HttpStatus.INTERNAL_SERVER_ERROR;

    const responseBody = {
      statusCode: httpStatus,
      timestamp: new Date().toISOString(),
      path: httpAdapter.getRequestUrl(ctx.getRequest()),
    };

    httpAdapter.reply(ctx.getResponse(), responseBody, httpStatus);
  }
}
```

* **HTTP exchange**:
  ```http
  GET /non-existent-route

  → 500 Internal Server Error
  {
    "statusCode": 500,
    "timestamp": "2026-05-23T08:35:00.000Z",
    "path": "/non-existent-route"
  }
  ```

## With ValidationPipe

`ValidationPipe` throws `BadRequestException` by default. Pair with a filter only when you need a custom error envelope; otherwise the built-in global filter is enough ([[nestjs/recipes/validation|validation recipe]]).

```http
// Request with invalid payload:
POST /users
Content-Type: application/json

{
  "email": "invalid-email-format"
}

// Default ValidationPipe 400 response:
HTTP/1.1 400 Bad Request
Content-Type: application/json; charset=utf-8

{
  "statusCode": 400,
  "message": [
    "email must be an email"
  ],
  "error": "Bad Request"
}
```

## Common errors

| Symptom                     | Likely cause                                                       |
| --------------------------- | ------------------------------------------------------------------ |
| Typed filter never runs     | Catch-all listed after typed filter in `@UseFilters` (worked example: [Catch-all ordering](#catch-all-ordering)) |
| "No HTTP adapter"           | `new Filter()` instead of class binding                            |
| Empty response after filter | `async catch()` rejected without await: use sync or handle promise |
