> Functions that run **before** [[nestjs/fundamentals/guards|guards]], [[nestjs/fundamentals/interceptors|interceptors]], [[nestjs/fundamentals/pipes|pipes]], and the handler. They see raw `req`/`res` and call `next()` or end the response.

## Signature

```typescript title="logger.middleware.ts"
import { Injectable, NestMiddleware } from "@nestjs/common";
import { NextFunction, Request, Response } from "express";

@Injectable()
export class LoggerMiddleware implements NestMiddleware {
  use(req: Request, res: Response, next: NextFunction): void | Promise<void> {
    console.log(`${req.method} ${req.url}`);
    next(); // omit this and the request hangs until the client times out
  }
}
```

<Aside type="note" title="No ExecutionContext">

Middleware cannot read `@Roles()`, the controller class, or which handler will run. That is why authorization and [[nestjs/recipes/validation|validation]] live in [[nestjs/fundamentals/guards|guards]] and [[nestjs/fundamentals/pipes|pipes]], not here.

</Aside>

## Bind middleware

<Steps>

1. **Pick a shape**: class (`NestMiddleware` + DI) or functional (plain `(req, res, next)` when you need no injections). See [functional middleware](https://docs.nestjs.com/middleware#functional-middleware).
2. **Pick a scope**: global `app.use()` in `main.ts` (no DI) or module `configure()` with `MiddlewareConsumer` (DI-aware).
3. **Match routes**: `forRoutes(CatsController)`, path strings, or [[nestjs/releases/v11|v11]] wildcards (`'*splat'`, `'{*splat}'`).
4. **Call `next()`**: or send a response; never return without doing one of those.

</Steps>

<Tabs>
  <TabItem label="Global (main.ts)">
    ```typescript title="main.ts"
    import { NestFactory } from "@nestjs/core";
    import { AppModule } from "./app.module";
    import { requestId } from "./request-id.middleware";

    async function bootstrap() {
      const app = await NestFactory.create(AppModule);
      app.use(requestId); // no Nest DI: plain Express middleware
      await app.listen(3000);
    }
    bootstrap();
    ```
  </TabItem>
  <TabItem label="Module (DI)">
    ```typescript title="app.module.ts"
    import { MiddlewareConsumer, Module, NestModule, RequestMethod } from "@nestjs/common";
    import { CatsController } from "./cats.controller";
    import { LoggerMiddleware } from "./logger.middleware";

    @Module({ controllers: [CatsController] })
    export class AppModule implements NestModule {
      configure(consumer: MiddlewareConsumer): void {
        consumer
          .apply(LoggerMiddleware)
          .exclude({ path: "cats/health", method: RequestMethod.GET })
          .forRoutes(CatsController);
      }
    }
    ```
    There is **no `APP_MIDDLEWARE` token**. Globals for other layers: [[nestjs/fundamentals/global-providers|global enhancers]].
  </TabItem>
</Tabs>

<Aside type="caution" title="Wildcard paths since NestJS 11">

Express v5 (default in Nest 11) uses **named** wildcards: `'*splat'` (subpaths only) or `'{*splat}'` (includes the base path). Legacy `'*'` and `'(.*)'` still work but warn at startup ([migration guide](https://github.com/nestjs/docs.nestjs.com/blob/master/content/migration.md#express-v5)).

</Aside>

## Middleware vs other layers

| Need | Layer | Why |
| --- | --- | --- |
| Raw `req`/`res` mutation (IDs, helmet, compression) | **[Middleware](#signature)** | Runs first; no handler metadata (see worked examples in [Recipes](#recipes)) |
| Allow/deny handler | [Guard](/knowledge-base/nestjs/fundamentals/guards/) | `ExecutionContext` + `@Roles()` metadata |
| Validate `@Body()` / `@Param()` | [Pipe](/knowledge-base/nestjs/fundamentals/pipes/) | Argument metadata |
| Wrap handler + response stream | [Interceptor](/knowledge-base/nestjs/fundamentals/interceptors/) | `next.handle()` |
| Map thrown errors to HTTP | [Exception filter](/knowledge-base/nestjs/fundamentals/exception-filters/) | Inside Nest's exception zone |

## Recipes

### Request ID on every response

Functional middleware: pair with [[nestjs/recipes/trace-id|trace IDs]] for `AsyncLocalStorage` logging.

```typescript title="request-id.middleware.ts"
import { randomUUID } from "node:crypto";
import { NextFunction, Request, Response } from "express";

export function requestId(req: Request, res: Response, next: NextFunction): void {
  const id = (req.headers["x-request-id"] as string) ?? randomUUID();
  req.headers["x-request-id"] = id;
  res.setHeader("x-request-id", id);
  next();
}
```

```http
// BEFORE: Outbound Request from Client (No x-request-id):
GET /users HTTP/1.1
Host: localhost:3000

// AFTER: Inbound request mutated by functional middleware and response header attached:
// Mutated Inbound request headers inside handler:
// req.headers['x-request-id'] = "1a8b9c0d-e1f2-3a4b-5c6d-7e8f9a0b1c2d"

// Resulting Response Headers received by client:
HTTP/1.1 200 OK
X-Request-Id: 1a8b9c0d-e1f2-3a4b-5c6d-7e8f9a0b1c2d
Content-Type: application/json; charset=utf-8
```

### Access log (HTTP layer)

| Question | Layer |
| --- | --- |
| Method, URL, status, duration | Middleware (`res.on("finish", ...)` worked example: [HttpLoggerMiddleware](#access-log-http-layer)) |
| Business events inside the handler | [Interceptor](/knowledge-base/nestjs/fundamentals/interceptors/) |

```typescript title="request-logger.middleware.ts"
import { Injectable, Logger, NestMiddleware } from "@nestjs/common";
import { NextFunction, Request, Response } from "express";

@Injectable()
export class HttpLoggerMiddleware implements NestMiddleware {
  private readonly logger = new Logger("HTTP");

  use(req: Request, res: Response, next: NextFunction): void {
    const started = Date.now();
    res.on("finish", () => {
      this.logger.log(
        `${req.method} ${req.originalUrl} ${res.statusCode} ${Date.now() - started}ms`,
      );
    });
    next();
  }
}
```

```text
// Sample Nest console access logs generated on response finish:
[Nest] 12345  - 05/23/2026, 8:31:00 AM     LOG [HTTP] GET /users 200 45ms
[Nest] 12345  - 05/23/2026, 8:31:05 AM     LOG [HTTP] POST /users/new 201 120ms
[Nest] 12345  - 05/23/2026, 8:31:10 AM    WARN [HTTP] GET /users/9999 404 12ms
```

### Raw body for signed webhooks

`express.json()` consumes the stream once. Stripe/GitHub sign **exact bytes**: re-serializing `req.body` breaks verification ([Stripe manual verify](https://docs.stripe.com/webhooks/signature#verify-manually)).

```json
// OUTCOME 1: Body parsed before signature verification (Fails!)
// Request payload:
POST /webhooks/stripe
Headers: Stripe-Signature: t=1614815340,v1=9c4a8a9a...
Body (as parsed by express.json()):
{ "id": "evt_123", "type": "payment_intent.succeeded" }

// In-code verification result:
// Stripe SDK throws SignatureVerificationError: "No signatures found matching the expected signature for payload"

// OUTCOME 2: Raw bytes verified (Success!)
// Raw body bytes passed:
Buffer.from('{"id":"evt_123","type":"payment_intent.succeeded"}')

// In-code verification result:
// Stripe SDK successfully constructs Event object: { id: "evt_123", ... }
```

```typescript title="main.ts"
import { json, raw } from "express";
import { NestFactory } from "@nestjs/core";
import { AppModule } from "./app.module";

async function bootstrap() {
  const app = await NestFactory.create(AppModule, { bodyParser: false });
  app.use("/webhooks/stripe", raw({ type: "application/json" }));
  app.use(json()); // all other routes
  await app.listen(3000);
}
bootstrap();
```

Or `{ rawBody: true }` + `RawBodyRequest`: [Raw body FAQ](https://docs.nestjs.com/faq/raw-body).

## Gotchas

<Aside type="caution" title="app.use() has no DI">

Injected services are `undefined` unless you bind via `MiddlewareConsumer.apply(ClassMiddleware)`.

</Aside>

<Aside type="caution" title="Default body parsers run first">

Nest registers `express.json()` / `urlencoded()` automatically. Custom parsers need `{ bodyParser: false }` on `NestFactory.create()` first.

</Aside>

<Aside type="note" title="HTTP only">

`MiddlewareConsumer` does not apply to WebSocket gateways or microservice handlers. Use guards/interceptors there ([hybrid apps](https://docs.nestjs.com/faq/hybrid-application)).

</Aside>

## Common errors

| Symptom | Likely cause |
| --- | --- |
| Request hangs | No `next()` and no `res.end()` (worked example: [LoggerMiddleware](#signature)) |
| Provider `undefined` in middleware | Used `app.use()` instead of `MiddlewareConsumer` (which bypasses DI; see correct [Module DI binding](#bind-middleware)) |
| Stripe signature fails | `json()` parsed body before verify: use `raw()` on webhook path (worked example: [Raw body for signed webhooks](#raw-body-for-signed-webhooks)) |
| `exclude()` ignored | Called after `forRoutes()`: order is `apply` → `exclude` → `forRoutes` ([worked example](#bind-middleware)) |
