## Why Turborepo over simple scripts

Standard NestJS monorepo mode shares a single `package.json` file at the root, which forces every microservice to inherit all dependencies. If a single background worker requires a heavy library, every other service in your cluster must download it in its production container.

Turborepo, paired with pnpm workspaces, resolves this dependency bleed by keeping package boundaries strict. It analyzes your dependency graph and accelerates your pipelines:

*   **Scoped dependencies**: Each Nest application and shared library maintains its own `package.json` manifest.
*   **Pipeline intelligence**: Turborepo schedules builds, tests, and lints in the correct topological order.
*   **Zero-effort [[nestjs/data/caching|caching]]**: Unchanged applications skip compiles and tests entirely, resolving instant feedback loops.
*   **Native dev servers**: Replaces brittle tools with native parallel task execution and clean, color-prefixed logging.

## Monorepo architecture

A standard high-performance NestJS monorepo uses the following structure:

```text
.
├── apps/
│   ├── api/                            # NestJS REST/GraphQL Application
│   │   ├── src/
│   │   │   ├── app.module.ts
│   │   │   └── main.ts
│   │   ├── package.json
│   │   └── tsconfig.json
│   └── worker/                         # NestJS Background Worker
│       ├── src/
│       │   ├── worker.module.ts
│       │   └── main.ts
│       ├── package.json
│       └── tsconfig.json
├── packages/                           # Shared Workspace Libraries
│   └── logger/                         # NestJS Shared Logging Module
│       ├── src/
│       │   ├── logger.module.ts
│       │   ├── logger.service.ts
│       │   └── index.ts
│       ├── package.json
│       └── tsconfig.json
├── pnpm-workspace.yaml                 # Defines workspace packages
├── turbo.json                          # Turborepo task pipeline configuration
├── package.json                        # Root monorepo manifest
└── tsconfig.json                       # Shared base TypeScript configuration
```

## Setup walkthrough

<Steps>

1.  **Initialize the workspace**

    Create a new directory and initialize a root workspace using pnpm, which is highly recommended for its symlink speed and strict dependency checks:

    ```bash
    mkdir nest-turbo-workspace
    cd nest-turbo-workspace
    pnpm init
    ```

    *Verification: Verify that a `package.json` file exists in the directory and that the terminal current working directory is `nest-turbo-workspace` before proceeding.*

    Create the `pnpm-workspace.yaml` file in the root to define your application and package folders:

    ```yaml
    packages:
      - "apps/*"
      - "packages/*"
    ```

2.  **Configure shared base configurations**

    Define a shared base `tsconfig.json` at the root that both applications and packages can extend to ensure compiler alignment:

    ```json
    {
      "compilerOptions": {
        "module": "commonjs",
        "declaration": true,
        "removeComments": true,
        "emitDecoratorMetadata": true,
        "experimentalDecorators": true,
        "allowSyntheticDefaultImports": true,
        "target": "es2021",
        "sourceMap": true,
        "incremental": true,
        "skipLibCheck": true,
        "strictNullChecks": true,
        "noImplicitAny": true,
        "strictBindCallApply": true,
        "forceConsistentCasingInFileNames": true,
        "noFallthroughCasesInSwitch": true
      }
    }
    ```

3.  **Scaffold a shared library**

    Create the shared logger library package inside `packages/logger/`. Shared libraries are housed in the `packages/` directory and compiled before the applications:

    ```bash
    mkdir -p packages/logger/src
    ```

    *Verification: Confirm that `packages/logger/src` has been successfully created in your project workspace tree.*

    Create the shared logger's `packages/logger/package.json` manifest:

    ```json
    {
      "name": "@repo/logger",
      "version": "1.0.0",
      "main": "dist/index.js",
      "types": "dist/index.d.ts",
      "scripts": {
        "build": "tsc"
      },
      "dependencies": {
        "@nestjs/common": "^11.0.0"
      },
      "devDependencies": {
        "typescript": "^5.0.0"
      }
    }
    ```

    Write the library's TypeScript [[nestjs/recipes/configuration|configuration]] in `packages/logger/tsconfig.json`:

    ```json
    {
      "extends": "../../tsconfig.json",
      "compilerOptions": {
        "outDir": "./dist",
        "rootDir": "./src"
      },
      "include": ["src/**/*"]
    }
    ```

    Create the module classes:

    ```typescript title="packages/logger/src/logger.service.ts"
    import { Injectable, Logger } from "@nestjs/common";

    @Injectable()
    export class SharedLoggerService {
      private readonly logger = new Logger("SharedWorkspace");

      logAction(action: string): void {
        this.logger.log(`Action recorded: ${action}`);
      }
    }
    ```

    ```typescript title="packages/logger/src/logger.module.ts"
    import { Module } from "@nestjs/common";
    import { SharedLoggerService } from "./logger.service";

    @Module({
      providers: [SharedLoggerService],
      exports: [SharedLoggerService],
    })
    export class SharedLoggerModule {}
    ```

    ```typescript title="packages/logger/src/index.ts"
    export * from "./logger.module";
    export * from "./logger.service";
    ```

4.  **Create the NestJS application**

    Scaffold a standard NestJS application under `apps/api/`. Workspace applications are housed under the `apps/` directory:

    ```bash
    mkdir -p apps/api/src
    ```

    *Verification: Confirm that the folder structure `apps/api/src` has been successfully created, which will contain our module classes and entrypoints.*

    Define the application's manifest in `apps/api/package.json`. Notice how it explicitly imports our shared workspace module `@repo/logger`:

    ```json
    {
      "name": "api",
      "version": "1.0.0",
      "scripts": {
        "build": "nest build",
        "start:dev": "nest start -w"
      },
      "dependencies": {
        "@nestjs/common": "^11.0.0",
        "@nestjs/core": "^11.0.0",
        "@nestjs/platform-express": "^11.0.0",
        "@repo/logger": "workspace:*",
        "reflect-metadata": "^0.2.0",
        "rxjs": "^7.8.0"
      },
      "devDependencies": {
        "@nestjs/cli": "^11.0.0",
        "@nestjs/schematics": "^11.0.0",
        "typescript": "^5.0.0"
      }
    }
    ```

    Create the standard application Nest config files.
    
    ```json title="apps/api/tsconfig.json"
    {
      "extends": "../../tsconfig.json",
      "compilerOptions": {
        "outDir": "./dist",
        "rootDir": "./src"
      },
      "include": ["src/**/*"]
    }
    ```

    ```json title="apps/api/nest-cli.json"
    {
      "$schema": "https://json.schemastore.org/nest-cli",
      "collection": "@nestjs/schematics",
      "sourceRoot": "src",
      "compilerOptions": {
        "deleteOutDir": true
      }
    }
    ```

    Now build the core entrypoint code for `apps/api/src/app.module.ts`:

    ```typescript title="apps/api/src/app.module.ts"
    import { Module } from "@nestjs/common";
    import { SharedLoggerModule } from "@repo/logger";

    @Module({
      imports: [SharedLoggerModule],
    })
    export class AppModule {}
    ```

    ```typescript title="apps/api/src/main.ts"
    import { NestFactory } from "@nestjs/core";
    import { AppModule } from "./app.module";
    import { SharedLoggerService } from "@repo/logger";

    async function bootstrap() {
      const app = await NestFactory.create(AppModule);
      
      const logger = app.get(SharedLoggerService);
      logger.logAction("API server bootstrap complete");
      
      await app.listen(3000);
    }
    bootstrap();
    ```

5.  **Configure Turborepo pipelines**

    Now install Turborepo as a root developer dependency:

    ```bash
    pnpm add -wD turbo
    ```

    *Verification: Verify that `turbo` is listed in your root `package.json` under `devDependencies` and is available to run via `pnpm exec turbo --version`.*

    Create a `turbo.json` configuration file at the root of your workspace to model task pipelines:

    ```json
    {
      "$schema": "https://turbo.build/schema.json",
      "tasks": {
        "build": {
          "dependsOn": ["^build"],
          "outputs": ["dist/**"]
        },
        "start:dev": {
          "cache": false,
          "persistent": true
        }
      }
    }
    ```

    *   **`dependsOn: ["^build"]`**: Ensures that if application `A` depends on shared library `B`, library `B` is built before application `A` executes its compilation.
    *   **`outputs: ["dist/**"]`**: Instructs Turborepo to cache the generated output directory. Running `turbo build` a second time restores this directory instantly.
    *   **`persistent: true`**: Tells Turborepo that this is a long-running watch command so it does not block subsequent operations or crash under parallel executions.

6.  **Run parallel tasks with Turborepo**

    Update your root `package.json` to orchestrate workspace-wide tasks:

    ```json
    {
      "name": "nest-turbo-workspace",
      "private": true,
      "scripts": {
        "build": "turbo build",
        "dev": "turbo start:dev"
      }
    }
    ```

    Run the dev task to start all Nest applications and watch local dependency changes simultaneously:

    ```bash
    pnpm dev
    ```

    *Verification: Verify that the command boots the workspace applications successfully. You should see parallel console outputs showing Turborepo running the `api:start:dev` task, standard Nest compilation watch logs, and the custom bootstrap message: `[Nest] ... LOG [SharedWorkspace] Action recorded: API server bootstrap complete`.*

    When you save changes to your shared module `@repo/logger`, the dev pipeline detects the updates, triggers rebuilds in topological order, and reboots the corresponding Nest servers.

</Steps>

## Production multi-stage Docker builds

Building container images for monorepos typically leads to bloated context sizes and slow build loops because of copy instructions invalidating cache layers. Turborepo addresses this with `turbo prune`, which isolates the target application's code and exact dependency workspace subset.

Here is the production-ready `Dockerfile` optimized for building the `api` app inside the monorepo:

```dockerfile
# Stage 1: Pruning step
FROM node:22-alpine AS pruner
WORKDIR /usr/src/app
RUN npm install -g turbo
COPY . .
# Isolates only the files required to build the 'api' application
RUN turbo prune api --out=json

# Stage 2: Workspace dependency setup
FROM node:22-alpine AS installer
WORKDIR /usr/src/app

# Install pnpm for package resolution
RUN npm install -g pnpm

# Copy package manifests from the isolated prune output
COPY --from=pruner /usr/src/app/out/json/ .

# Install dependencies based on pnpm lockfiles
RUN pnpm install --frozen-lockfile

# Stage 3: Builder step
FROM node:22-alpine AS builder
WORKDIR /usr/src/app
RUN npm install -g pnpm

# Copy installer dependencies and isolated source code
COPY --from=installer /usr/src/app/ .
COPY --from=pruner /usr/src/app/out/full/ .

# Compile the target application
RUN pnpm run build --filter=api

# Stage 4: Runner step
FROM node:22-alpine AS runner
WORKDIR /usr/src/app

ENV NODE_ENV=production

# Copy compiled resources and production-grade workspace configurations
COPY --from=builder /usr/src/app/package.json ./package.json
COPY --from=builder /usr/src/app/pnpm-workspace.yaml ./pnpm-workspace.yaml
COPY --from=builder /usr/src/app/node_modules ./node_modules
COPY --from=builder /usr/src/app/apps/api ./apps/api
COPY --from=builder /usr/src/app/packages ./packages

EXPOSE 3000

CMD ["node", "apps/api/dist/main"]
```

### Build cache optimization highlights

1.  **Pruning Isolation**: The `turbo prune` utility constructs a subset containing only the targets and local dependency packages, guaranteeing changes to non-related workspace packages do not invalidate our Docker build cache.
2.  **Deterministic Dependency Installation**: Pnpm uses hard links to populate node folders quickly. In multi-stage container builds, copying only manifest files and lockfiles before source files ensures package layer compilation is cached.
3.  **Ultra-Slim Execution Layer**: The runner stage inherits only the compiled outputs and active dependencies, ensuring minimal footprint sizes while resolving internal module resolution rules cleanly.

| Tooling Feature | Native Nest CLI Monorepo | Turborepo Workspaces (pnpm) | Nx Platform |
| :--- | :--- | :--- | :--- |
| **[Dependency Bleed](#why-turborepo-over-simple-scripts)** | High (Single shared root manifest) | None (Strictly isolated packages) | None (Enforced modular boundaries) |
| **[Build Caching](#setup-walkthrough)** | None | Full Local and Remote caching | Advanced caching with remote store |
| **[Orchestration](#setup-walkthrough)** | Brittle manual script triggers | Automated DAG-based pipeline graph | Advanced execution graph and analyzers |
| **Code Generation** | Native `nest g` schematics | Manually configured or raw templates | Rich, extensible code generators |
| **Ideal Use Case** | Single-team, highly uniform Nest servers | High-performance, multi-service workspaces | Enterprise multi-stack monorepos |

## Common gotchas

<Aside type="caution" title="Do not forget to define dependencies in app manifests">
If application `api` imports a service from `@repo/logger` but misses declaring `"@repo/logger": "workspace:*"` inside its own `package.json`, pnpm will not link the packages correctly. The app will fail to compile under `turbo build` because the dependency path resolution fails.
</Aside>

<Aside type="caution" title="Ensure workspace imports are built first">
When compiling a NestJS app that imports local workspace dependencies, make sure that library packages are built before application compilation starts. If your workspace builds fail at startup, check that your `turbo.json` config has `"build": { "dependsOn": ["^build"] }` active.
</Aside>
