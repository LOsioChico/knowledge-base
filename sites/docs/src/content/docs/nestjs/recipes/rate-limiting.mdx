> Cap how many requests a single client can fire at your API in a time window. `@nestjs/throttler` ships a [[nestjs/fundamentals/guards|guard]] you bind globally: per-route overrides come from two decorators. In-memory store by default, Redis when you scale past one instance.

<Aside type="tip" title="Prerequisites">
Before diving into rate limiting, make sure you understand:
- [[nestjs/fundamentals/guards|Guards]]: since rate limiting is enforced in NestJS via `ThrottlerGuard` which runs within the NestJS Guard layer.
- [[nestjs/recipes/configuration|Configuration]]: since production rate limiters are configured asynchronously via `ConfigService`.
- [[nestjs/fundamentals/request-lifecycle|Request Lifecycle]]: since when chaining global enhancers (like authentication guards), registration order decides which provider runs first.
- [[nestjs/auth/jwt-strategy|JWT Strategy & Authentication]]: since per-user rate limiting requires extracting user IDs from request metadata populated by authentication guards.
</Aside>

## Setup

<Steps>

1. **Install `@nestjs/throttler`**: Install the package as a dependency. Version 5 or higher is required to support the modern array-based multiple-throttler syntax and millisecond `ttl` units.
   
   <PackageManagers pkg="@nestjs/throttler" pkgManagers={['npm', 'pnpm', 'yarn', 'bun']} />

   *Verification: Confirm that `@nestjs/throttler` appears under `dependencies` in your `package.json` with a version `^5.0.0` or higher before proceeding.*

2. Register the module and global guard:

   ```typescript title="app.module.ts"
   import { Module } from "@nestjs/common";
   import { APP_GUARD } from "@nestjs/core";
   import { ThrottlerModule, ThrottlerGuard, seconds } from "@nestjs/throttler";

   @Module({
     imports: [
       ThrottlerModule.forRoot([
         {
           ttl: seconds(60),
           limit: 10,
         },
       ]),
     ],
     providers: [
       {
         provide: APP_GUARD,
         useClass: ThrottlerGuard,
       },
     ],
   })
   export class AppModule {}
   ```

   - `ThrottlerModule.forRoot([{ ttl, limit }])`: `ttl` is the sliding window duration in **milliseconds** (use `seconds()` or `minutes()` helper functions), `limit` is the maximum number of requests allowed in that window.
   - `APP_GUARD` registers `ThrottlerGuard` globally with dependency injection.

3. Exceed the limit: when a client fires an 11th request within the sliding window, the server rejects the request:

   Request:

   ```http
   GET / HTTP/1.1
   Host: localhost:3000
   ```

   Response headers:

   ```http
   HTTP/1.1 429 Too Many Requests
   Content-Type: application/json
   Retry-After: 60
   ```

   Response body:

   ```json
   {
     "statusCode": 429,
     "message": "ThrottlerException: Too Many Requests"
   }
   ```

</Steps>

## Per-Route Overrides

You can override or bypass the global rate limiter using decorators on individual controllers or route handlers.

<Tabs>
  <TabItem label="@Throttle()">
    Tighten or loosen the global bucket on a specific route. The outer key matches the **throttler name**: use `default` for a single unnamed bucket:

    ```typescript title="auth.controller.ts"
    import { Controller, Post, Body } from "@nestjs/common";
    import { Throttle, seconds } from "@nestjs/throttler";

    export interface LoginDto {
      readonly email: string;
      readonly password?: string;
    }

    @Controller("auth")
    export class AuthController {
      @Throttle({ default: { limit: 5, ttl: seconds(60) } })
      @Post("login")
      async login(@Body() dto: LoginDto) {
        return { success: true };
      }
    }
    ```

    The `@Throttle` decorator overrides the global configuration, setting a dedicated limit of 5 requests per minute specifically for the `login` endpoint.
  </TabItem>
  <TabItem label="@SkipThrottle()">
    Opt out entirely for health check endpoints or third-party webhooks:

    ```typescript title="health.controller.ts"
    import { Controller, Get } from "@nestjs/common";
    import { SkipThrottle } from "@nestjs/throttler";

    @SkipThrottle()
    @Controller("health")
    export class HealthController {
      @Get()
      check() {
        return { status: "OK" };
      }
    }
    ```
  </TabItem>
</Tabs>

## Multiple Named Throttlers

You can stack multiple throttlers to handle both immediate bursts (e.g., max 3 requests per second) and sustained traffic (e.g., max 100 requests per minute) concurrently.

```typescript title="app.module.ts"
import { Module } from "@nestjs/common";
import { APP_GUARD } from "@nestjs/core";
import { ThrottlerModule, ThrottlerGuard, seconds, minutes } from "@nestjs/throttler";

@Module({
  imports: [
    ThrottlerModule.forRoot([
      { name: "burst", ttl: seconds(1), limit: 3 },
      { name: "sustained", ttl: minutes(1), limit: 100 },
    ]),
  ],
  providers: [
    {
      provide: APP_GUARD,
      useClass: ThrottlerGuard,
    },
  ],
})
export class AppModule {}
```

```typescript title="reports.controller.ts"
import { Controller, Get } from "@nestjs/common";
import { Throttle, SkipThrottle, seconds } from "@nestjs/throttler";

@Controller("reports")
export class ReportsController {
  @Throttle({ burst: { limit: 1, ttl: seconds(1) } })
  @Get("expensive")
  expensive() {
    return { data: "huge PDF" };
  }

  @SkipThrottle({ burst: true }) // Skips the burst limit, still applies the sustained limit
  @Get("dashboard")
  dashboard() {
    return { status: "ready" };
  }
}
```

### Limit Behavior (Show-Don't-Tell)

When hitting `GET /reports/expensive` twice in a single second:

<Tabs>
  <TabItem label="Request 1 (0ms)">
    ```http
    GET /reports/expensive HTTP/1.1
    Host: localhost:3000
    ```
    ```json
    HTTP/1.1 200 OK
    Content-Type: application/json

    {
      "data": "huge PDF"
    }
    ```
  </TabItem>
  <TabItem label="Request 2 (200ms)">
    ```http
    GET /reports/expensive HTTP/1.1
    Host: localhost:3000
    ```
    ```json
    HTTP/1.1 429 Too Many Requests
    Content-Type: application/json

    {
      "statusCode": 429,
      "message": "ThrottlerException: Too Many Requests"
    }
    ```
  </TabItem>
</Tabs>

For the `GET /reports/dashboard` handler, the `@SkipThrottle({ burst: true })` decorator disables the `burst` bucket entirely, meaning the client is exempt from the 1-second burst rate limit on this endpoint. The global `sustained` bucket (100 requests per minute) remains active as defined in the global AppModule.

## Reverse Proxies and Header Security

By default, `ThrottlerGuard` uses the incoming request IP address (`req.ip`) as the unique identifier for rate limiting. When your application runs behind a reverse proxy (like Cloudflare, AWS ALB, Nginx, or an API Gateway), `req.ip` will resolve to the **internal IP of the proxy**, meaning every single user will share the same bucket and throttle each other.

```http
// Outbound Client A Request (Spoofed/Proxied):
GET /users HTTP/1.1
Host: api.example.com
X-Forwarded-For: 203.0.113.195

// Outbound Client B Request (From separate WAN IP):
GET /users HTTP/1.1
Host: api.example.com
X-Forwarded-For: 198.51.100.42

// Server-Side Behavior (Without proxy trust):
// NestJS sees both requests coming from Nginx/ALB internal IP: 10.0.0.15
// Client A consumes the remaining 10 hits. Client B immediately receives:
HTTP/1.1 429 Too Many Requests
Content-Type: application/json

{
  "statusCode": 429,
  "message": "ThrottlerException: Too Many Requests"
}
```

To solve this, you must configure NestJS to trust headers like `X-Forwarded-For`.

### 1. Configure Express Proxy Trust

```typescript title="main.ts"
import { NestFactory } from "@nestjs/core";
import { NestExpressApplication } from "@nestjs/platform-express";
import { AppModule } from "./app.module";

async function bootstrap() {
  // Cast to NestExpressApplication to access Express-specific API
  const app = await NestFactory.create<NestExpressApplication>(AppModule);
  
  // Configure Express proxy trust parameters
  app.set("trust proxy", "loopback"); // Trusts only local proxy connections
  
  await app.listen(3000);
}
bootstrap();
```

<Aside type="caution" title="Blindly trusting proxy headers is a security vulnerability">

Setting `app.set('trust proxy', true)` instructs the server to blindly trust the leftmost IP in the client-sent `X-Forwarded-For` header. A malicious client can easily spoof their IP address by passing a custom `X-Forwarded-For` header, bypassing all rate-limiting constraints.

Always use a narrow setting:
- `"loopback"`: Trusts local loopback addresses (`127.0.0.1`, `::1`).
- Specific IP ranges: Pass your reverse proxy CIDR blocks (e.g., `"10.0.0.0/8"`, Cloudflare IP subnets) to guarantee only authentic proxy headers are trusted.

</Aside>

### 2. Custom Secure Proxy Guard

If your application runs behind reverse proxies (like Cloudflare, AWS ALB, or Nginx), you must extract the real client IP address securely. Since `ThrottlerGuard` relies on the request object injected by the underlying HTTP platform adapter, you should implement an adapter-specific guard for your platform. The implementation is different for the Express and Fastify adapters.

<Tabs>
  <TabItem label="Express HTTP Adapter">
    For the default Express HTTP adapter, type the request as `Request` from `"express"` and extract the leftmost address from `req.ips`:

    ```typescript title="trace/throttler-behind-proxy.guard.ts"
    import { Injectable } from "@nestjs/common";
    import { ThrottlerGuard } from "@nestjs/throttler";
    import { Request } from "express";

    @Injectable()
    export class ThrottlerBehindProxyGuard extends ThrottlerGuard {
      protected async getTracker(req: Request): Promise<string> {
        // req.ips contains the array of downstream proxy hops. The leftmost IP is the client.
        return req.ips?.length ? req.ips[0] : (req.ip ?? "unknown");
      }
    }
    ```
  </TabItem>
  <TabItem label="Fastify HTTP Adapter">
    For the Fastify HTTP adapter, type the request as `FastifyRequest` from `"fastify"` and retrieve the IP address as follows:

    ```typescript title="trace/throttler-behind-proxy.guard.ts"
    import { Injectable } from "@nestjs/common";
    import { ThrottlerGuard } from "@nestjs/throttler";
    import { FastifyRequest } from "fastify";

    @Injectable()
    export class ThrottlerBehindProxyGuard extends ThrottlerGuard {
      protected async getTracker(req: FastifyRequest): Promise<string> {
        // req.ips contains proxy hops if Fastify is configured to trust proxies.
        return req.ips?.length ? req.ips[0] : (req.ip ?? "unknown");
      }
    }
    ```

    Ensure you have enabled proxy trusting in your Fastify bootstrap adapter setup:
    ```typescript title="main.ts"
    import { NestFactory } from "@nestjs/core";
    import { FastifyAdapter, NestFastifyApplication } from "@nestjs/platform-fastify";
    import { AppModule } from "./app.module";

    async function bootstrap() {
      const app = await NestFactory.create<NestFastifyApplication>(
        AppModule,
        new FastifyAdapter({ trustProxy: true }), // Enable proxy trust in Fastify
      );
      await app.listen(3000);
    }
    bootstrap();
    ```
  </TabItem>
</Tabs>

Register your custom guard as the global guard in your module:

```typescript title="app.module.ts" del={3, 18} ins={3-4, 18}
import { Module } from "@nestjs/common";
import { APP_GUARD } from "@nestjs/core";
import { ThrottlerModule, seconds } from "@nestjs/throttler";
import { ThrottlerBehindProxyGuard } from "./trace/throttler-behind-proxy.guard";

@Module({
  imports: [
    ThrottlerModule.forRoot([
      {
        ttl: seconds(60),
        limit: 10,
      },
    ]),
  ],
  providers: [
    {
      provide: APP_GUARD,
      useClass: ThrottlerBehindProxyGuard,
    },
  ],
})
export class AppModule {}
```

## Dynamic and Per-User Throttling

### 1. Throttling by User ID

For authenticated routes, rate-limiting by IP address is insufficient because users behind the same office NAT will block each other. It is far more robust to rate-limit based on the authenticated `user.id`.

```typescript title="trace/user-throttler.guard.ts"
import { Injectable } from "@nestjs/common";
import { ThrottlerGuard } from "@nestjs/throttler";
import { Request } from "express";

@Injectable()
export class UserThrottlerGuard extends ThrottlerGuard {
  protected async getTracker(req: Request): Promise<string> {
    const user = (req as Request & { readonly user?: { readonly id: string } }).user;
    return user?.id ?? req.ip ?? "anonymous";
  }
}
```

Note: when combining multiple global guards, ensure your authentication guard (e.g. `JwtAuthGuard`) is registered **before** the `ThrottlerGuard` in `AppModule`. NestJS executes guards in the order they are registered in the providers array.

### 2. Asynchronous Dynamic Configuration

If you need to fetch throttler limits dynamically from a database, remote [[nestjs/recipes/configuration|configuration]] server, or environment variables at application startup, use `forRootAsync`:

```typescript title="app.module.ts"
import { Module } from "@nestjs/common";
import { ConfigModule, ConfigService } from "@nestjs/config";
import { APP_GUARD } from "@nestjs/core";
import { ThrottlerModule, seconds } from "@nestjs/throttler";
import { ThrottlerBehindProxyGuard } from "./trace/throttler-behind-proxy.guard";

@Module({
  imports: [
    ConfigModule.forRoot({ isGlobal: true }),
    ThrottlerModule.forRootAsync({
      imports: [ConfigModule],
      inject: [ConfigService],
      useFactory: (config: ConfigService) => [
        {
          ttl: seconds(config.get<number>("THROTTLE_TTL_SEC", 60)),
          limit: config.get<number>("THROTTLE_LIMIT", 100),
        },
      ],
    }),
  ],
  providers: [
    {
      provide: APP_GUARD,
      useClass: ThrottlerBehindProxyGuard,
    },
  ],
})
export class AppModule {}
```

## Distributed Storage (Redis Scaling)

The default in-memory storage driver stores rate counters inside the Node.js process heap memory. In production, when you run multiple instances or containers behind a load balancer, client requests will hit different servers.

Because the ALB distributes the load across processes, the local in-memory counters remain independent. A single client can make up to 10 requests to Instance A and up to 10 requests to Instance B simultaneously, effectively doubling their allowance to 20 requests per minute without any instance-level rate limits triggering. In-memory storage completely fails to coordinate and enforce the global 10-request limit.

```text
Scenario: Limit is 10 requests/min. Two container instances run behind a Round-Robin ALB.

Request 1  -> ALB -> Instance A (hits: 1/10) -> HTTP 200
Request 2  -> ALB -> Instance B (hits: 1/10) -> HTTP 200
...
Request 20 -> ALB -> Instance B (hits: 10/10) -> HTTP 200

Outcome: Client successfully fires 20 requests in 1 minute, bypassing the global 10-request limit because counters are not shared.
```

To scale horizontally, you must wire up a distributed Redis store.

### 1. Install Redis Integration Packages

To share rate-limiting counters across all application nodes, install the NestJS Redis storage provider along with `ioredis`:

<PackageManagers pkg="@nest-lab/throttler-storage-redis ioredis" pkgManagers={['npm', 'pnpm', 'yarn', 'bun']} />

*Verification: Verify that `@nest-lab/throttler-storage-redis` and `ioredis` are listed in your `dependencies` block in `package.json` and can be imported in your Nest modules.*

### 2. Configure Redis Storage

```typescript title="app.module.ts"
import { Module } from "@nestjs/common";
import { APP_GUARD } from "@nestjs/core";
import { ThrottlerModule, seconds } from "@nestjs/throttler";
import { ThrottlerStorageRedisService } from "@nest-lab/throttler-storage-redis";
import Redis from "ioredis";
import { ThrottlerBehindProxyGuard } from "./trace/throttler-behind-proxy.guard";

@Module({
  imports: [
    ThrottlerModule.forRoot({
      throttlers: [
        {
          ttl: seconds(60),
          limit: 10,
        },
      ],
      // Share counters across all application nodes using Redis
      storage: new ThrottlerStorageRedisService(
        new Redis(process.env.REDIS_URL ?? "redis://localhost:6379"),
      ),
    }),
  ],
  providers: [
    {
      provide: APP_GUARD,
      useClass: ThrottlerBehindProxyGuard,
    },
  ],
})
export class AppModule {}
```

## Gotchas and Best Practices

<Aside type="caution" title="Throttler ttl unit changed in v5">

Pre-v5 versions of `@nestjs/throttler` accepted `ttl` in **seconds**. In `@nestjs/throttler` v5 and higher, `ttl` is parsed in **milliseconds**. Passing a raw value like `ttl: 60` now sets the window to 60 **milliseconds** instead of 60 seconds, which will block all clients immediately. Always use helper methods like `seconds(60)` or pass the raw millisecond value (`60000`).

</Aside>

<Aside type="caution" title="WebSocket Gateways Require Custom Overrides">

The default `ThrottlerGuard` extracts the HTTP execution context. WebSockets have a completely different primitive architecture. To rate limit socket connections, subclass `ThrottlerGuard` and override `handleRequest` utilizing `switchToWs()` to extract the WebSocket connection:

```typescript title="gateways/ws-throttler.guard.ts"
import { Injectable, ExecutionContext } from "@nestjs/common";
import { ThrottlerGuard } from "@nestjs/throttler";

@Injectable()
export class WsThrottlerGuard extends ThrottlerGuard {
  async handleRequest(context: ExecutionContext, limit: number, ttl: number): Promise<boolean> {
    const client = context.switchToWs().getClient();
    const tracker = client.conn.remoteAddress; // Socket tracking identifier
    const key = this.generateKey(context, tracker, "ws");
    
    const { totalHits } = await this.storageService.increment(key, ttl);
    if (totalHits > limit) {
      throw new Error("WS Rate Limit Exceeded");
    }
    return true;
  }
}
```

</Aside>
