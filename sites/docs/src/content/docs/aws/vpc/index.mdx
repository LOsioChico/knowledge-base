> Amazon VPC is your private slice of the AWS network: isolated address space carved into **subnets** per Availability Zone, with route tables, security groups, and gateways controlling ingress and egress. Every regional resource ([[aws/ec2|EC2]], [[aws/rds|RDS]], VPC-attached [[aws/lambda|Lambda]], [[aws/ecs|ECS]] tasks) lives in one.

## TL;DR

- **Primary CIDR at creation** (e.g. `10.0.0.0/16`); add secondary CIDRs later but cannot shrink the primary.
- **Subnet = AZ + CIDR slice**. Public subnet routes to an Internet Gateway; private egress via NAT Gateway (~$0.045/hr + per-GB).
- **Security group = stateful** instance firewall. **Network ACL = stateless** subnet filter. SGs are the workhorse.
- **VPC endpoints** let private subnets reach AWS APIs ([[aws/s3|S3]], [[aws/dynamodb|DynamoDB]], [[aws/sqs|SQS]]) without internet: saves NAT cost.
- **Default VPC** works for sandboxes; too permissive for production.

## When to use

- **Custom VPC** for production, private databases, compliance.
- **Default VPC** for throwaway experiments.
- **Avoid** multiple unconnected VPCs when one suffices: peering and Transit Gateway add cost.
