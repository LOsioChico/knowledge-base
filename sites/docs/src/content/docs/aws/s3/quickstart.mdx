## Before you start

- AWS CLI profile that resolves to a writable account: [[aws/cli/profiles-and-credentials|profiles and credentials]]. Verify `Account` in the JSON matches the account you intend to bill:

  ```bash
  aws --profile $AWS_PROFILE sts get-caller-identity
  ```

- Region pinned forever at bucket creation; pick the Region closest to readers.

Shared variables for every command below:

```bash
export AWS_PROFILE=$AWS_PROFILE
export REGION=$REGION
export ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
export BUCKET=quickstart-${ACCOUNT_ID}-${REGION}
```

The `<purpose>-<account>-<region>` shape avoids global namespace collisions. For account-regional namespace see [[aws/s3|S3]].

## 1. Create the bucket

`us-east-1` is the only Region that omits `--create-bucket-configuration`. After create, layer public-access block, versioning, and default encryption (three settings every new bucket should start with):

```bash
if [ "$REGION" = "us-east-1" ]; then
  aws s3api create-bucket --bucket "$BUCKET" --region "$REGION"
else
  aws s3api create-bucket --bucket "$BUCKET" --region "$REGION" \
    --create-bucket-configuration LocationConstraint="$REGION"
fi

aws s3api put-public-access-block --bucket "$BUCKET" \
  --public-access-block-configuration \
    BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true

aws s3api put-bucket-versioning --bucket "$BUCKET" \
  --versioning-configuration Status=Enabled

aws s3api put-bucket-encryption --bucket "$BUCKET" \
  --server-side-encryption-configuration \
    '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}'
```

<Aside type="caution" title="Versioning without lifecycle grows the bill">

Each version is the full object. Add [[aws/s3/lifecycle-rules|lifecycle]] to expire noncurrent versions before real data lands.

</Aside>

## 2. Upload an object

`aws s3 cp` is the high-level move-bytes command; expect an `upload:` line naming the destination key:

```bash
echo "hello s3" > hello.txt
aws s3 cp hello.txt "s3://$BUCKET/hello.txt"
   # upload: ./hello.txt to s3://quickstart-123456789012-us-east-1/hello.txt
```

## 3. List and download

Confirm the object appears in `ls`, then copy it back locally and read the file:

```bash
aws s3 ls "s3://$BUCKET/"
aws s3 cp "s3://$BUCKET/hello.txt" downloaded.txt
cat downloaded.txt
   # hello s3
```

## 4. Share without making the bucket public

Sign a time-limited HTTPS URL so someone without IAM credentials can download one object (default 3600 seconds):

```bash
aws s3 presign "s3://$BUCKET/hello.txt" --expires-in 3600
```

Anyone with the link can `curl` it until the signature expires.

## 5. Clean up

Versioning is on: plain `aws s3 rm --recursive` leaves noncurrent versions and blocks `delete-bucket`. Delete every version and delete marker, then remove the bucket:

```bash
aws s3api delete-objects --bucket "$BUCKET" \
  --delete "$(aws s3api list-object-versions --bucket "$BUCKET" \
    --query '{Objects: [Versions, DeleteMarkers][].{Key:Key,VersionId:VersionId}}' \
    --output json)"

aws s3api delete-bucket --bucket "$BUCKET" --region "$REGION"
```

<Aside type="caution" title="Recursive rm does not remove versions">

On versioned buckets it adds delete markers; bytes remain. Use `delete-objects` + `list-object-versions` to empty truly.

</Aside>
