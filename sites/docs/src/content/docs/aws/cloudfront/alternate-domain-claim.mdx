> [[aws/cloudfront|CloudFront]] alternate domain names are globally unique across accounts. Amplify domain moves can leave **ghost claims** — retries stack faster than DNS can chase them.

## Symptom

```text
One or more aliases specified for the distribution includes an incorrectly
configured DNS record that points to another CloudFront distribution.
```

DNS is correct, nothing else claims the alias today, error persists. Each retry provisions a **new** CloudFront target — updating DNS is a losing race.

## Diagnose

```bash
aws cloudfront list-distributions \
  --query "DistributionList.Items[?Aliases.Items != null && contains(Aliases.Items, 'app.example.com')].{Id:Id,Domain:DomainName,Status:Status}" \
  --output table

aws amplify get-domain-association \
  --app-id <APP_ID> --domain-name example.com \
  --query 'domainAssociation.{status:domainStatus,reason:statusReason}' \
  --output json
```

If you control the holding distribution, prefer documented [`update-domain-association`](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/alternate-domain-names-move-options.html). Workaround below is when source is unreachable or Amplify-managed.

<Aside type="caution" title="Retries make it worse">

Failed Amplify associations can leave claims for hours. Each retry adds another ghost. Switch strategy instead of clicking Retry.

</Aside>

## Workaround: bring your own ACM certificate

Empirical unblock when vanilla retries fail ([CNAME restrictions](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/CNAMEs.html#alternate-domain-names-restrictions)):

<Steps>

1. **Request public ACM cert** in `us-east-1` (required for CloudFront aliases):

   ```bash
   aws acm request-certificate \
   --domain-name example.com \
   --subject-alternative-names '*.example.com' \
   --validation-method DNS
   ```

2. **Add DNS validation CNAME** from `describe-certificate` output.

3. **Wait for ISSUED**:

   ```bash
   aws acm wait certificate-validated --certificate-arn <CERT_ARN>
   ```

4. **Attach custom cert to Amplify**:

   ```bash
   aws amplify update-domain-association \
   --app-id <APP_ID> \
   --domain-name example.com \
   --certificate-settings type=CUSTOM,customCertificateArn=<CERT_ARN> \
   --sub-domain-settings prefix=app,branchName=main
   ```

5. **Poll** until `domainStatus: AVAILABLE`.

</Steps>

## Cheaper paths that fail

| Path | Why it fails |
| --- | --- |
| Console Retry | New distribution + new ghost claim |
| Wait minutes | Claims measured in hours |
| Delete + recreate same prefix | Same as Retry |
| New prefix (`app2`) | Works if prefix is flexible |

## Recovery without custom cert

Stop retries; wait 2–4+ hours; attempt once. Escalate via [AWS Support](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/alternate-domain-names-move-options.html#alternate-domain-names-move-contact-support) to release alias.

## Operational notes

- ACM auto-renews while validation CNAME stays in DNS.
- `*.example.com` does not cover nested subdomains — add SANs.
- Same ghost store affects non-Amplify CloudFront distributions.
