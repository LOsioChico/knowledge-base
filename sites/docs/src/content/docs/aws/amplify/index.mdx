> AWS Amplify Hosting is git-push-or-zip-deploy frontend hosting: Amplify builds, ships to an internal [[aws/cloudfront|CloudFront]] distribution, serves on `*.amplifyapp.com` or custom domains. One CLI surface (`aws amplify`).

## TL;DR

- **Four primitives**: App → Branch → Deployment/Job → Domain association.
- **Two ship paths**: git-connected auto-build or manual zip ([[aws/s3/presigned-urls|presigned upload URL]] + `start-deployment`).
- **Hosting = CloudFront + ACM (us-east-1) + Route 53**: Amplify owns all three.
- **Custom domain = `create-domain-association`**: provisions cert and alias.
- **Amplify Gen 2** co-deploys data/auth/storage from one project.

## When to use

- **Use Amplify** for SPAs/SSR frontends, PR previews, "git push to deploy".
- **Don't use Amplify** when you need explicit CloudFront behaviors, multiple origins, or Lambda@Edge control: use S3 + CloudFront.
- **Don't use Amplify** as sole backend compute: use [[aws/lambda|Lambda]], ECS, or App Runner.

Amplify provisions CloudFront you won't see in `cloudfront list-distributions`. Domain moves hit global CNAME uniqueness: [[aws/cloudfront/alternate-domain-claim|ghost claims]].

## Job types

Amplify deployment jobs support three execution modes via `--job-type`:

- **`RELEASE`**: Triggers a brand new build execution environment, pulls the latest source code from your Git provider, and compiles your project using your build specifications.
- **`RETRY`**: Retries a build execution using the exact same commit hash and build inputs as the last run.
- **`WEB_HOOK`**: Deploys via an incoming webhook notification trigger.
