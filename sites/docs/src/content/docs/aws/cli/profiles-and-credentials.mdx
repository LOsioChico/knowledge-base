> Use named CLI profiles to drive multiple AWS accounts from one shell; verify which account each profile resolves to with `aws sts get-caller-identity` before any write.

<Aside type="tip" title="Prerequisites">

None. This is the **foundational entry point** of the **[[aws|AWS Serverless Track]]**.

</Aside>

## Profile shape

[Named profiles](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html) live in `~/.aws/config` (settings) and `~/.aws/credentials` (long-lived keys). Select via `--profile <name>` or `AWS_PROFILE`; default is `default`.

```ini
# ~/.aws/config
[profile pentica]
region = us-east-1
output = json

[profile we4labs]
region = us-east-1
output = json
```

```ini
# ~/.aws/credentials
[pentica]
aws_access_key_id = AKIA...
aws_secret_access_key = ...
```

SSO-backed profiles use [`aws configure sso`](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sso.html) and `aws sso login --profile <name>`: no long-lived keys on disk.

## Inspect what's configured

```bash
aws configure list-profiles
aws configure list --profile pentica
aws configure get region --profile pentica
```

<Aside type="caution" title="list-profiles is CLI v2 only">

Documented under v2 ([source](https://docs.aws.amazon.com/cli/latest/reference/configure/list-profiles.html)); absent from v1. If it errors, read `~/.aws/credentials` and `~/.aws/config` directly.

</Aside>

## Confirm which account a profile points at

[`aws sts get-caller-identity`](https://docs.aws.amazon.com/cli/latest/reference/sts/get-caller-identity.html) returns account, ARN, and UserId for resolved credentials:

```bash
aws sts get-caller-identity --profile pentica --output json
# {
#   "UserId": "AIDA...",
#   "Account": "123456789012",
#   "Arn": "arn:aws:iam::123456789012:user/developer-administrator"
# }

aws sts get-caller-identity --profile we4labs --query Arn --output text
```

Run this for every profile before any [[aws/kms|KMS]], [[aws/iam|IAM]], or [[aws/rds|RDS]] write.

## Common patterns

- **Per-shell pinning**: `export AWS_PROFILE=pentica`: still run `sts get-caller-identity`.
- **Per-command**: `aws --profile we4labs --region us-east-1 <service> <verb>` for self-contained runbooks.
- **Cross-account assume-role**: base profile + derived profile with `role_arn` + `source_profile` in config: [[aws/recipes/cross-account-role-pattern|cross-account role pattern]].

## Credential resolution order

Env vars (`AWS_ACCESS_KEY_ID`, …) → `--profile` → `AWS_PROFILE` → `default` → EC2 IMDS. First usable identity wins; `sts get-caller-identity` shows which source matched.
