> A scoped resource is one whose cleanup is wired to the lifetime of an `Effect`, so the runtime guarantees release on success, failure, and interruption.
> Prerequisite: [[effect-ts/retry-and-schedule|Retry & Schedule]]

<Steps>

1. Pick the primitive (`acquireUseRelease` vs `acquireRelease` + `Scope`).
2. Register cleanup (release / finalizer).
3. Discharge `Scope` with `Effect.scoped` or `Layer.scoped`.
4. Compose with timeout, retry, and [[effect-ts/concurrency|interrupt]]: finalizers still run.

</Steps>

## Why this exists

`try/finally` does not run when an `await` is abandoned by cancellation or when a parent [[effect-ts/what-is-effect|fiber]] is interrupted. Effect registers finalizers; the runtime runs them in reverse order when the scope closes ([Scope docs](https://effect.website/docs/resource-management/scope/)).

Per [`Effect.acquireRelease` JSDoc](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/Effect.ts#L5371-L5398), acquire and release run **uninterruptibly** so half-open resources do not leak.

## The four primitives

| API | Lifetime owner | Reach for |
| --- | --- | --- |
| `Effect.acquireUseRelease` | One expression | Acquire → use → release in a single block; `R` stays `never`; [example](#acquire-use-release-example) |
| `Effect.acquireRelease` | Enclosing `Scope` | Resource reused across steps; needs `Effect.scoped` or `Layer.scoped`; [example](#acquire-release-example) |
| `Effect.addFinalizer` | Enclosing `Scope` | Register cleanup next to the code that needs it; sees `Exit`; [example](#add-finalizer-example) |
| `Effect.ensuring` | Wrapped effect | Side-effect cleanup with no resource value; no `Scope` in `R`; [example](#ensuring-example) |

<Tabs>
  <TabItem label="acquireUseRelease">
    <a id="acquire-use-release-example"></a>

    ```ts twoslash title="acquire-release.ts"
    import { Console, Effect } from "effect";

    interface Page {
      readonly url: string;
      readonly close: () => Promise<void>;
    }

    const openPage = (url: string): Promise<Page> =>
      Promise.resolve({
        url,
        close: () => {
          console.log(`closed ${url}`);
          return Promise.resolve();
        },
      });

    const program = Effect.acquireUseRelease(
      Effect.tryPromise({
        try: () => openPage("https://example.com"),
        catch: (cause) => new Error(`open failed: ${String(cause)}`),
      }),
      (page) => Console.log(`scraping ${page.url}`),
      (page) => Effect.promise(() => page.close()),
    );

    Effect.runPromise(program);
    // scraping https://example.com
    // closed https://example.com
    ```

    `release` runs if `use` fails or the effect is interrupted.

  </TabItem>
  <TabItem label="acquireRelease + scoped">
    <a id="acquire-release-example"></a>

    ```ts twoslash title="ensure-finalizer.ts"
    import { Effect } from "effect";

    interface DbPool {
      readonly query: (sql: string) => Promise<unknown>;
      readonly end: () => Promise<void>;
    }

    const connect = Effect.tryPromise({
      try: () =>
        Promise.resolve<DbPool>({
          query: (sql) => Promise.resolve({ sql }),
          end: () => {
            console.log("pool closed");
            return Promise.resolve();
          },
        }),
      catch: (cause) => new Error(`connect failed: ${String(cause)}`),
    });

    const pool = Effect.acquireRelease(connect, (p) => Effect.promise(() => p.end()));

    const work = Effect.gen(function* () {
      const db = yield* pool;
      return yield* Effect.promise(() => db.query("SELECT 1"));
    });

    Effect.runPromise(Effect.scoped(work));
    // pool closed
    ```

    `Scope` appears in `R` until `Effect.scoped` discharges it. Same pattern as [[effect-ts/layers-and-di|Layer.scoped]].

  </TabItem>
  <TabItem label="addFinalizer">
    <a id="add-finalizer-example"></a>

    ```ts twoslash title="add-finalizer.ts"
    import { Console, Effect, Exit } from "effect";

    const program = Effect.gen(function* () {
      yield* Effect.addFinalizer((exit) =>
        Exit.isSuccess(exit)
          ? Console.log("committed")
          : Console.log(`rolled back: ${exit._tag}`),
      );
      return "result";
    });

    Effect.runPromise(Effect.scoped(program)).then(console.log);
    // committed
    // result
    ```

    Use when cleanup depends on how the scope ended, not a single acquire/release pair.

  </TabItem>
  <TabItem label="ensuring">
    <a id="ensuring-example"></a>

    ```ts twoslash title="scope-make.ts"
    import { Console, Effect } from "effect";

    const work = Console.log("doing work").pipe(
      Effect.tap(() => Effect.fail(new Error("boom"))),
    );

    const guarded = work.pipe(Effect.ensuring(Console.log("cleanup ran")));

    Effect.runPromiseExit(guarded);
    // doing work
    // cleanup ran
    ```

    No `Scope` in `R`. Prefer `acquireRelease` when you have a resource value to release ([Effect.ts#L5700-L5703](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/Effect.ts#L5700-L5703)).

## Deep-dive: Intuition-first resource lifecycle

To understand how scopes operate in production, consider a multi-step database transaction. If any step fails or is timed out by an orchestrator, we must guarantee that the database connection is cleanly returned to the pool, preventing connection leaks.

By wrapping our resource initialization in `Effect.acquireRelease`, the Effect runtime automatically tracks the resource and wires its release logic to the enclosing `Scope` context.

```ts twoslash title="resource-lifecycle.ts"
import { Effect, Console } from "effect";

class DbConnection {
  constructor(readonly id: number) {}
  
  query(sql: string): Effect.Effect<string, Error> {
    return Effect.succeed(`Success: '${sql}' executed on connection ${this.id}`);
  }
  
  close(): Effect.Effect<void> {
    return Console.log(`Connection ${this.id} cleanly closed.`);
  }
}

let connectionCounter = 0;

// Factory function simulating high-overhead resource creation
const connect = (): Effect.Effect<DbConnection, Error> =>
  Effect.gen(function* () {
    const id = ++connectionCounter;
    yield* Console.log(`Initializing connection ${id} handshake...`);
    return new DbConnection(id);
  });

// acquireRelease couples the resource acquisition with its release/close finalizer
const managedConnection = Effect.acquireRelease(
  connect(),
  (connection) => connection.close()
);

const executeTransaction = Effect.gen(function* () {
  yield* Console.log("Starting transactional work...");
  
  // Yielding the managed resource pulls the Scope requirement into the environment type
  const conn = yield* managedConnection;
  
  const res1 = yield* conn.query("SELECT * FROM products");
  yield* Console.log(res1);
  
  const res2 = yield* conn.query("UPDATE inventory SET stock = 10");
  yield* Console.log(res2);
  
  yield* Console.log("Transaction successfully completed.");
});

// We discharge the Scope dependency using Effect.scoped at the execution boundary
Effect.runPromise(Effect.scoped(executeTransaction));
```

### Visualizing execution output

When executing the above program, the terminal output demonstrates that the finalizer runs **automatically** after the scope of the program terminates, guaranteeing no leaked resources:

```text
Starting transactional work...
Initializing connection 1 handshake...
Success: 'SELECT * FROM products' executed on connection 1
Success: 'UPDATE inventory SET stock = 10' executed on connection 1
Transaction successfully completed.
Connection 1 cleanly closed.
```

If a query in the block throws a failure (for example, a database exception or query execution timeout), the finalizer still executes cleanly:

```text
Starting transactional work...
Initializing connection 1 handshake...
Success: 'SELECT * FROM products' executed on connection 1
// Query 2 fails with: Error: UPDATE query timeout!
Connection 1 cleanly closed.
```

## Finalizer ordering

Finalizers run **LIFO** when the scope closes ([Scope docs](https://effect.website/docs/resource-management/scope/)):

```ts twoslash title="finalizer-ordering.ts"
import { Console, Effect } from "effect";

const program = Effect.gen(function* () {
  yield* Effect.addFinalizer(() => Console.log("finalizer 1"));
  yield* Effect.addFinalizer(() => Console.log("finalizer 2"));
  yield* Effect.addFinalizer(() => Console.log("finalizer 3"));
});

Effect.runPromise(Effect.scoped(program));
// finalizer 3
// finalizer 2
// finalizer 1
```

## Retry, timeout, and interrupt

When `Effect.timeout` or a parent [[effect-ts/concurrency|interrupt]] cancels work, nested scopes run finalizers before propagating failure. Wrapping `acquireUseRelease` in `Effect.retry` gives each attempt a fresh resource; the previous one is released before the next try: the pattern used in [[effect-ts/fault-tolerant-ingestion|fault-tolerant ingestion]].

```ts twoslash title="retry-timeout-interrupt.ts"
import { Effect, Console } from "effect";

let attempts = 0;

const program = Effect.acquireUseRelease(
  Effect.sync(() => {
    attempts++;
    console.log(`[Acquire] Resource attempt ${attempts}`);
    return { id: attempts };
  }),
  (res) =>
    Effect.gen(function* () {
      console.log(`[Use] Using resource ${res.id}`);
      if (res.id < 3) {
        return yield* Effect.fail("Temporary failure");
      }
      return "Success!";
    }),
  (res) => Effect.sync(() => console.log(`[Release] Releasing resource ${res.id}`))
).pipe(
  Effect.retry({ times: 3 })
);

Effect.runPromise(program);
// [Acquire] Resource attempt 1
// [Use] Using resource 1
// [Release] Releasing resource 1
// [Acquire] Resource attempt 2
// [Use] Using resource 2
// [Release] Releasing resource 2
// [Acquire] Resource attempt 3
// [Use] Using resource 3
// success returned: "Success!"
```

<Aside type="caution" title="Forgot Effect.scoped">

If `R` still contains `Scope` at the runner, finalizers are not discharged at your boundary. One-shot: wrap with `Effect.scoped`. Long-lived: `Layer.scoped`.

</Aside>

<Aside type="caution" title="Acquire and release are uninterruptible">

Default `acquireRelease` cannot be interrupted mid-open/mid-close. Use `Effect.acquireReleaseInterruptible` only when you explicitly need a killable long handshake ([Effect.ts#L5476-L5484](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/Effect.ts#L5476-L5484)).

</Aside>
