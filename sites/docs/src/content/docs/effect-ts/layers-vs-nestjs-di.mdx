> Effect [[effect-ts/layers-and-di|layers]] and NestJS's IoC container both wire dependencies. They differ on **when** missing deps surface, **how** graphs compose, and **how** cleanup is modeled.

> Prerequisite: [[effect-ts/layers-and-di|Layers and DI]]

## TL;DR

- **Effect**: missing services are a **type error** (`R` must be `never` to run).
- **NestJS**: missing providers fail at **bootstrap** with "Nest can't resolve dependencies…".
- **Sharing**: Nest singletons per app; Effect memoizes per `Effect.provide` graph (use `ManagedRuntime` for app-wide).
- **Cleanup**: `Layer.scoped` vs `OnModuleDestroy` / shutdown hooks (opt-in on Nest).
- **Together**: Nest owns the provider; Effect runs programs via `ManagedRuntime` inside methods.

## Mental model

| Concept | Effect | NestJS |
| --- | --- | --- |
| [Declaration](#the-same-graph-logger--greeter) | `Context.Tag` / `Effect.Service` | `@Injectable()` |
| [Implementation](#the-same-graph-logger--greeter) | `Layer.succeed` / `effect` / `scoped` | `providers: [...]` |
| [Wiring](#the-same-graph-logger--greeter) | `Effect.provide` narrows `R` | Module `imports` / `providers` |
| [Missing dep](#the-same-graph-logger--greeter) | Compile error | Bootstrap exception |
| [Default lifetime](#scope-and-memoization) | Per provision graph | Singleton |
| [Per-request](#scope-and-memoization) | Fresh layer per handler | [Scope.REQUEST](/knowledge-base/nestjs/fundamentals/global-providers/) |
| [Cleanup](/knowledge-base/effect-ts/scoped-resources/) | `Layer.scoped` / `acquireRelease` | [Lifecycle hooks](/knowledge-base/nestjs/fundamentals/lifecycle-hooks/) |
| [Tests](#tests) | Swap `Layer` | [overrideProvider](/knowledge-base/nestjs/recipes/testing/) |

    ```ts twoslash title="effect-logger-greeter.ts"
    import { Context, Effect, Layer } from "effect";

    class Logger extends Context.Tag("Logger")<
      Logger,
      { readonly log: (msg: string) => Effect.Effect<void> }
    >() {}

    class Greeter extends Context.Tag("Greeter")<
      Greeter,
      { readonly greet: (name: string) => Effect.Effect<void> }
    >() {}

    const LoggerLive = Layer.succeed(Logger, {
      log: (msg) => Effect.sync(() => console.log(`[INFO] ${msg}`)),
    });

    const GreeterLive = Layer.effect(
      Greeter,
      Effect.gen(function* () {
        const logger = yield* Logger;
        return {
          greet: (name: string) => logger.log(`hello, ${name}`),
        };
      }),
    );

    const AppLive = Layer.provide(GreeterLive, LoggerLive);

    const program = Effect.gen(function* () {
      const greeter = yield* Greeter;
      yield* greeter.greet("world");
    });

    Effect.runPromise(program.pipe(Effect.provide(AppLive)));
    // [INFO] hello, world
    ```

## Where they diverge

### Compile-time `R` vs bootstrap DI

```ts twoslash title="compile-time-r.ts"
// @errors: 2345
import { Context, Effect } from "effect";

class Db extends Context.Tag("Db")<
  Db,
  { readonly query: (sql: string) => Effect.Effect<void> }
>() {}

const program = Effect.gen(function* () {
  const db = yield* Db;
  yield* db.query("select 1");
});

Effect.runPromise(program);
```

NestJS resolves the graph at bootstrap ([custom providers](https://docs.nestjs.com/fundamentals/custom-providers#di-fundamentals)).

### Custom Injection Tokens: `@Inject` vs `Context.Tag`

In NestJS, provider identity defaults to the class itself, but you can decouple implementation from interface using custom string or symbol injection tokens with `@Inject()`:

```typescript title="nestjs-inject-token.ts"
// NestJS: Decouple boundary using an injection token
import { Injectable, Inject, Module } from "@nestjs/common";

export const LOGGER_TOKEN = Symbol("LOGGER_TOKEN");

export interface ILogger {
  log(msg: string): void;
}

@Injectable()
export class ConsoleLogger implements ILogger {
  log(msg: string) { console.log(msg); }
}

@Injectable()
export class GameService {
  // Injecting the boundary
  constructor(@Inject(LOGGER_TOKEN) private readonly logger: ILogger) {}
}

@Module({
  providers: [
    {
      provide: LOGGER_TOKEN,
      useClass: ConsoleLogger,
    },
    GameService,
  ],
})
export class GameModule {}
```

In Effect, **every service boundary is declared explicitly as a Tag**. The Tag acts as the unique runtime symbol and the compiler's type index simultaneously:

```typescript twoslash title="effect-context-tag.ts"
// Effect: The Tag is both the token and the type interface
import { Context, Effect } from "effect";

export class Logger extends Context.Tag("Logger")<
  Logger,
  { readonly log: (msg: string) => Effect.Effect<void> }
>() {}

// Injecting the boundary (inferred in R)
export const logMessage = Effect.gen(function* () {
  const logger = yield* Logger;
  return yield* logger.log("decoupled");
});
```

### Dynamic Modules and Provider Bindings vs Layer

NestJS uses **[[nestjs/recipes/dynamic-modules|Dynamic Modules]]** (`register()`, `forRoot()`) to construct provider configurations dynamically (e.g., passing a [[nestjs/recipes/configuration|configuration]] object or reading from environment variables at startup):

```typescript title="nestjs-dynamic-module.ts"
// NestJS: Dynamic Module configuration
import { Module, DynamicModule } from "@nestjs/common";

export const DB_CONNECTION = Symbol("DB_CONNECTION");
export class DatabaseConnection {
  constructor(public readonly url: string) {}
}

@Module({})
export class DatabaseModule {
  static forRoot(dbUrl: string): DynamicModule {
    return {
      module: DatabaseModule,
      providers: [
        {
          provide: DB_CONNECTION,
          useFactory: () => new DatabaseConnection(dbUrl),
        },
      ],
      exports: [DB_CONNECTION],
    };
  }
}
```

In Effect, **Layers are values** that can be composed and constructed dynamically using ordinary functions and standard functional operators. There is no special container ceremony or dynamic module API:

```typescript twoslash title="effect-layer-composition.ts"
// Effect: Dynamic Layer factory function
import { Context, Effect, Layer } from "effect";

export class Database extends Context.Tag("Database")<
  Database,
  { readonly query: (sql: string) => Effect.Effect<string> }
>() {}

export const makeDatabaseLive = (dbUrl: string) =>
  Layer.succeed(Database, {
    query: (sql) => Effect.succeed(`url: ${dbUrl} | query: ${sql}`),
  });

// Compose dynamically at the app entrypoint
const AppLive = makeDatabaseLive(process.env.DATABASE_URL || "fallback-url");
```

### Scope and memoization

Nest providers are **singletons** unless scoped (see [[nestjs/fundamentals/global-providers|injection scopes]] for details). Effect layers memoize **per `Effect.provide`** ([memoization docs](https://effect.website/docs/requirements-management/layer-memoization/)).

Here is how a Nest singleton is shared across the provider graph, compared to a request-scoped provider that instantiates a fresh class per request execution path:

```typescript title="nestjs-scope.ts"
// NestJS: Singleton vs Request Scope lifetime
import { Injectable, Scope } from "@nestjs/common";

let next = 0;

// Singleton (Default): created once, shared everywhere
@Injectable()
export class SingletonCounter {
  readonly id = ++next;
}

// Request-scoped: fresh instance per request execution path
@Injectable({ scope: Scope.REQUEST })
export class RequestScopedCounter {
  readonly id = ++next;
}
```

```text
// Outcome with SingletonCounter (injected in ServiceA and ServiceB):
ServiceA counter ID: 1
ServiceB counter ID: 1 // Same instance shared everywhere!

// Outcome with RequestScopedCounter (fresh instance for request path):
Request 1 -> ServiceA counter ID: 2, ServiceB counter ID: 2
Request 2 -> ServiceA counter ID: 3, ServiceB counter ID: 3 // Isolated across requests!
```

```ts twoslash title="effect-scope.ts"
import { Context, Effect, Layer, ManagedRuntime } from "effect";

class Counter extends Context.Tag("Counter")<
  Counter,
  { readonly id: number }
>() {}

let next = 0;
const CounterLive = Layer.effect(
  Counter,
  Effect.sync(() => {
    next += 1;
    return { id: next };
  }),
);

Effect.runSync(
  Effect.flatMap(Counter, (c) => Effect.sync(() => console.log(`a: ${c.id}`))).pipe(
    Effect.provide(CounterLive),
  ),
);
Effect.runSync(
  Effect.flatMap(Counter, (c) => Effect.sync(() => console.log(`b: ${c.id}`))).pipe(
    Effect.provide(CounterLive),
  ),
);
// a: 1
// b: 2

const runtime = ManagedRuntime.make(CounterLive);
const run = async () => {
  await runtime.runPromise(
    Effect.flatMap(Counter, (c) => Effect.sync(() => console.log(`c: ${c.id}`))),
  );
  await runtime.runPromise(
    Effect.flatMap(Counter, (c) => Effect.sync(() => console.log(`d: ${c.id}`))),
  );
};
run();
// c: 3
// d: 3
```

`ManagedRuntime` ≈ one Nest singleton for Effect services.

### Resource cleanup

Effect: [[effect-ts/scoped-resources|Layer.scoped]] + `acquireRelease`: release on [[effect-ts/concurrency|interrupt]] without extra flags.

NestJS: `OnModuleDestroy` / `OnApplicationShutdown`: requires `app.close()` or `enableShutdownHooks()` (see [[nestjs/fundamentals/lifecycle-hooks|lifecycle hooks]] for details).

### Tests

```ts twoslash title="effect-test-layer.ts"
import { Context, Effect, Layer } from "effect";

class Logger extends Context.Tag("Logger")<
  Logger,
  { readonly log: (msg: string) => Effect.Effect<void> }
>() {}

class Greeter extends Context.Tag("Greeter")<
  Greeter,
  { readonly greet: (name: string) => Effect.Effect<void> }
>() {}

const LoggerLive = Layer.succeed(Logger, {
  log: (msg) => Effect.sync(() => console.log(`[INFO] ${msg}`)),
});

const GreeterLive = Layer.effect(
  Greeter,
  Effect.gen(function* () {
    const logger = yield* Logger;
    return { greet: (name: string) => logger.log(`hello, ${name}`) };
  }),
);

const LoggerTest = Layer.succeed(Logger, {
  log: () => Effect.void,
});

const AppTest = Layer.provide(GreeterLive, LoggerTest);

const program = Effect.gen(function* () {
  const greeter = yield* Greeter;
  yield* greeter.greet("world");
});

Effect.runPromise(program.pipe(Effect.provide(AppTest)));
```

NestJS provides a [[nestjs/recipes/testing|testing]] module builder that allows mocking or overriding providers at bootstrap:

```typescript title="nestjs-test-module.ts"
import { Injectable } from "@nestjs/common";
import { Test } from "@nestjs/testing";

@Injectable()
class Logger {
  log(msg: string) {
    console.log(`[INFO] ${msg}`);
  }
}

@Injectable()
class Greeter {
  constructor(private readonly logger: Logger) {}
  greet(name: string) {
    this.logger.log(`hello, ${name}`);
  }
}

async function runTest() {
  const moduleRef = await Test.createTestingModule({
    providers: [Greeter, Logger],
  })
    .overrideProvider(Logger)
    .useValue({
      log: () => {}, // Mocked: void logger in test
    })
    .compile();

  const greeter = moduleRef.get(Greeter);
  greeter.greet("world");
}
runTest();
// (Logger.log is bypassed: no output generated in test stdout)
```

## Using both together

```ts twoslash title="effect-with-nestjs.ts"
import { Context, Data, Effect, Layer, ManagedRuntime } from "effect";

class Http extends Context.Tag("Http")<
  Http,
  { readonly get: (url: string) => Effect.Effect<string, HttpError> }
>() {}

class HttpError extends Data.TaggedError("HttpError")<{
  readonly cause: unknown;
}> {}

const HttpLive = Layer.succeed(Http, {
  get: (url) =>
    Effect.tryPromise({
      try: () => fetch(url).then((r) => r.text()),
      catch: (e) => new HttpError({ cause: e }),
    }),
});

// Nest side (shape only — install @nestjs/common in your app):
// @Injectable()
// export class CatalogService implements OnApplicationShutdown {
//   private readonly runtime = ManagedRuntime.make(HttpLive);
//   fetchListing(id: string) {
//     return this.runtime.runPromise(
//       Effect.gen(function* () {
//         const http = yield* Http;
//         return yield* http.get(`https://catalog.example.com/items/${id}`).pipe(
//           Effect.retry({ times: 3 }),
//         );
//       }),
//     );
//   }
//   async onApplicationShutdown() {
//     await this.runtime.dispose();
//   }
// }

const runtime = ManagedRuntime.make(HttpLive);

const run = async () => {
  await runtime.runPromise(
    Effect.gen(function* () {
      const http = yield* Http;
      return yield* http.get("https://example.com").pipe(Effect.retry({ times: 3 }));
    }),
  );

  await runtime.dispose();
};
run();
```

<Aside type="caution" title="Do not merge the containers">

`Context.Tag("Logger")` and `@Injectable() class Logger` are different identities. Pick one container per service lifetime.

</Aside>
