> Schema is the runtime boundary for `Effect<A, E, R>` programs: it checks unknown input, derives TypeScript types from the same declaration, and keeps parse failures in the typed `E` channel.

<Steps>

1. **Stop trusting** `as` at JSON, config, and HTTP boundaries.
2. **Declare** the expected shape with `Schema.Struct`.
3. **Infer** the TypeScript type from the schema instead of duplicating an interface.
4. **Decode** `unknown` into an `Effect` that succeeds with the typed value or fails with a parse error.
5. **Map** parse errors into your own domain tag before exposing service APIs.

</Steps>

## Before you start

Install the core `effect` package first. After the command finishes, confirm your package manager added `effect` to `package.json`; the examples use `Effect`, `Schema`, `ParseResult`, and `Data` from that package ([installation](https://effect.website/docs/getting-started/installation/#manual-installation)).

```bash
bun add effect
```

## The boundary problem

`JSON.parse` returns `any`, and `as Todo` only changes what TypeScript believes. It does not check the value that came from the outside world.

```ts twoslash
interface Todo {
  readonly id: number;
  readonly title: string;
  readonly completed: boolean;
}

const raw = '{"id":"1","title":"Write docs"}';
const todo = JSON.parse(raw) as Todo;

console.log(todo.id + 1);
// "11", because id was actually a string

console.log(todo.completed);
// undefined, because the field was missing
```

The code type-checks, but the runtime value is still malformed. Schema puts the check at the boundary instead of letting the bad shape move deeper into the program.

<Aside type="caution" title="as is not validation">

Use `as` only when some other code already proved the shape. At an untrusted boundary, the value is `unknown` until a parser accepts it.

</Aside>

## 1. Declare the shape once

`Schema.Struct` builds an object schema from field schemas ([structs](https://effect.website/docs/schema/basic-usage/#structs), [`Schema.Struct`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/Schema.ts#L2907-L2943)). Primitive schemas use PascalCase names such as `Schema.String`, `Schema.Number`, and `Schema.Boolean` ([primitives](https://effect.website/docs/schema/basic-usage/#primitives)).

```ts twoslash
import { Schema } from "effect";

const Todo = Schema.Struct({
  id: Schema.Number,
  title: Schema.String,
  completed: Schema.Boolean,
});
```

The schema is a runtime value. You can pass it to decoders, formatters, encoders, and other schema combinators.

## 2. Infer the TypeScript type

Do not write a separate `interface Todo` and hope it stays in sync. `Schema.Schema.Type<typeof Todo>` extracts the decoded TypeScript type from the schema ([type extraction](https://effect.website/docs/schema/getting-started/#type), [source](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/Schema.ts#L302-L319)).

```ts twoslash
import { Schema } from "effect";

const Todo = Schema.Struct({
  id: Schema.Number,
  title: Schema.String,
  completed: Schema.Boolean,
});

type Todo = Schema.Schema.Type<typeof Todo>;
//   ^?

const ok: Todo = {
  id: 1,
  title: "Write docs",
  completed: false,
};
```

The decoded type is the type your business logic should consume. The schema remains the source of truth.

<Aside type="note" title="Encoded and decoded can differ">

Schema also exposes `Schema.Schema.Encoded<typeof Todo>` for the input side of a schema ([encoded type](https://effect.website/docs/schema/getting-started/#encoded)). For a plain `Struct`, encoded and decoded shapes are the same. Transformation schemas can decode one shape and encode another.

```ts twoslash
import { Schema } from "effect";

const User = Schema.Struct({
  id: Schema.NumberFromString,
  name: Schema.String,
});

type User = Schema.Schema.Type<typeof User>;
//   ^?

type UserEncoded = Schema.Schema.Encoded<typeof User>;
//   ^?
```

</Aside>

## 3. Decode success

Use `Schema.decodeUnknown(schema)(input)` when the value came from `JSON.parse`, `Response.json()`, environment variables, CLI arguments, or any source you cannot type-check ahead of time. The API returns an `Effect` that succeeds with the decoded value or fails with `ParseResult.ParseError` ([decodeUnknown](https://effect.website/docs/schema/getting-started/#decodeunknown), [source](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/Schema.ts#L555-L566)).

```ts twoslash
import { Effect, Schema } from "effect";

const Todo = Schema.Struct({
  id: Schema.Number,
  title: Schema.String,
  completed: Schema.Boolean,
});

const input: unknown = {
  id: 1,
  title: "Write docs",
  completed: false,
};

const decoded = Schema.decodeUnknown(Todo)(input);
//    ^?

console.log(Effect.runSync(decoded));
// { id: 1, title: 'Write docs', completed: false }
```

The type tells the story: `decoded` is an `Effect` whose success is the inferred `Todo`, whose error is a parse error, and whose requirements are `never`.

## 4. Decode failure

Bad input stays in the `E` channel. Use `runSyncExit` or `Effect.either` when demonstrating a failure path so the example shows the value instead of throwing at the runner.

```ts twoslash
import { Effect, Exit, ParseResult, Schema } from "effect";

const Todo = Schema.Struct({
  id: Schema.Number,
  title: Schema.String,
  completed: Schema.Boolean,
});

const badInput: unknown = {
  id: "1",
  title: "Write docs",
};

const decoded = Schema.decodeUnknown(Todo)(badInput).pipe(
  Effect.mapError(ParseResult.TreeFormatter.formatErrorSync),
);

const exit = Effect.runSyncExit(decoded);
console.log(exit._tag);
// Failure

if (Exit.isFailure(exit)) {
  console.log(exit.cause._tag);
  console.log(String(exit.cause));
}
// Fail
// { readonly id: number; readonly title: string; readonly completed: boolean }
// └─ ["id"]
//    └─ Expected number, actual "1"
```

Schema parse failures are tagged `ParseResult.ParseError` values whose `issue` describes the parse problem ([parse error docs](https://effect.website/docs/schema/getting-started/#parseerror), [source](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/ParseResult.ts#L181-L218)). `ParseResult.TreeFormatter.formatErrorSync` turns the parse error into a readable tree for logs or your own error object.

<Aside type="caution" title="runSync throws on unhandled E">

`Schema.decodeUnknown(Todo)(badInput)` has a non-`never` error channel. `Effect.runSync` throws a `FiberFailure` when that error is not handled first. Use `runSyncExit`, `Effect.either`, or map and handle the error before crossing the application edge.

</Aside>

## 5. Map parse errors into a domain tag

Raw parse errors are useful inside a boundary adapter. A service API should usually expose an error name that matches the domain, then compose like any other [[effect-ts/typed-errors|typed error]]. `Effect.mapError` transforms the error channel without touching the success value ([mapError](https://effect.website/docs/error-management/error-channel-operations/#maperror), [source](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/internal/core.ts#L1042-L1076)).

```ts twoslash
import { Data, Effect, ParseResult, Schema } from "effect";

class ParseFailure extends Data.TaggedError("ParseFailure")<{
  readonly issues: string;
}> {}

const Todo = Schema.Struct({
  id: Schema.Number,
  title: Schema.String,
  completed: Schema.Boolean,
});

type Todo = Schema.Schema.Type<typeof Todo>;

const parseTodo = (input: unknown): Effect.Effect<Todo, ParseFailure> =>
  Schema.decodeUnknown(Todo)(input).pipe(
    Effect.mapError(
      (error) =>
        new ParseFailure({
          issues: ParseResult.TreeFormatter.formatErrorSync(error),
        }),
    ),
  );

const safeTitle = (input: unknown) =>
  parseTodo(input).pipe(
    Effect.map((todo) => todo.title),
    Effect.catchTag("ParseFailure", (error) =>
      Effect.succeed(`bad todo: ${error.issues.split("\n")[0]}`),
    ),
  );

console.log(Effect.runSync(safeTitle({ id: "1", title: "Write docs" })));
// bad todo: { readonly id: number; readonly title: string; readonly completed: boolean }
```

Now callers handle `ParseFailure`, not a low-level parser detail.

## 6. Put Schema in a small boundary adapter

Keep Schema at the edge: parse the outside value once, then pass the decoded type through the rest of the program.

<Tabs>
  <TabItem label="Boundary adapter">
    ```ts twoslash
    import { Data, Effect, ParseResult, Schema } from "effect";

    class NetworkError extends Data.TaggedError("NetworkError")<{
      readonly cause: unknown;
    }> {}

    class ParseFailure extends Data.TaggedError("ParseFailure")<{
      readonly issues: string;
    }> {}

    const Todo = Schema.Struct({
      id: Schema.Number,
      title: Schema.String,
      completed: Schema.Boolean,
    });

    type Todo = Schema.Schema.Type<typeof Todo>;

    const fetchJson = (): Effect.Effect<unknown, NetworkError> =>
      Effect.tryPromise({
        try: () =>
          Promise.resolve({ id: 1, title: "Write docs", completed: false }),
        catch: (cause) => new NetworkError({ cause }),
      });

    const parseTodo = (input: unknown): Effect.Effect<Todo, ParseFailure> =>
      Schema.decodeUnknown(Todo)(input).pipe(
        Effect.mapError(
          (error) =>
            new ParseFailure({
              issues: ParseResult.TreeFormatter.formatErrorSync(error),
            }),
        ),
      );

    const loadTodo = Effect.gen(function* () {
      const json = yield* fetchJson();
      return yield* parseTodo(json);
    });

    Effect.runPromise(loadTodo).then(console.log);
    // { id: 1, title: 'Write docs', completed: false }
    ```

  </TabItem>
  <TabItem label="Type story">

## Common gotchas

<Aside type="caution" title="Do not parse twice">

Decode at the boundary, then pass the inferred `Todo` type inward. Re-decoding the same value inside domain functions is noise and makes it harder to see where untrusted data enters.

</Aside>

<Aside type="caution" title="Use decodeUnknown for unknown input">

`Response.json()`, `JSON.parse`, environment variables, and CLI input are untrusted values. `decodeUnknown` is the safe default for those boundaries because its input is `unknown`.

</Aside>

<Aside type="note" title="Transforms are the second layer">

Schema can model different encoded and decoded shapes, like `Schema.NumberFromString`. Start with boundary validation first; add transformations when you need to cross from wire shape to domain shape in a controlled way.

</Aside>
