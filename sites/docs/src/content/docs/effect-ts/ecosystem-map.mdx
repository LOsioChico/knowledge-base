> Every package from the [`Effect-TS/effect` monorepo](https://github.com/Effect-TS/effect/tree/main/packages). Core ships as `effect`; integrations ship as `@effect/*`.

> Prerequisite: [[effect-ts/what-is-effect|What is Effect]]

## How packages are laid out

`effect` holds `Effect<A, E, R>`, runners, [[effect-ts/schema|Schema]], `Layer`, `Stream`, `Schedule`, `Fiber`, `Scope`, and combinators ([`packages/effect`](https://github.com/Effect-TS/effect/tree/main/packages/effect)). Everything else adds a runtime adapter, domain (HTTP, SQL, AI), or tooling.

`@effect/sql`, `@effect/ai`, and `@effect/platform` fan out into driver/provider sub-packages (tables below).

Before picking a package: [[effect-ts/quickstart|Quickstart]] (core only), [[effect-ts/layers-and-di|Layers and DI]] (how `@effect/*` enters `R`), [[effect-ts/composition|Composition]] (same `pipe` / `gen` idioms everywhere).

## Core packages

| Package            | What it is                                                                                                                                     | Reach for          | Skip when                                    |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ | -------------------------------------------- |
| `effect`           | Core types, runtime, [Schema](/knowledge-base/effect-ts/schema/), `Layer`, `Stream`, … (worked example: [Quickstart](/knowledge-base/effect-ts/quickstart/))   | Always             | Never                                        |
| `@effect/platform` | Platform-agnostic HTTP, FS, terminal, workers ([`package.json`](https://github.com/Effect-TS/effect/blob/main/packages/platform/package.json)) | Cross-runtime apps | Single-runtime-only scripts with native APIs |

**Runtime adapters** (pick one):

| Adapter                    | Runtime |
| -------------------------- | ------- |
| `@effect/platform-node`    | Node.js |
| `@effect/platform-bun`     | Bun     |
| `@effect/platform-browser` | Browser |

## Domain packages

| Package                     | Reach for                                                                                                                         | Skip when                                 |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| `@effect/cli`               | Typed CLI with subcommands ([`cli` package.json](https://github.com/Effect-TS/effect/blob/main/packages/cli/package.json))        | One-off `process.argv` scripts            |
| `@effect/sql` + one driver  | Type-safe SQL + `Layer` clients (see worked database operations in [Fault-tolerant ingestion](/knowledge-base/effect-ts/fault-tolerant-ingestion/))   | Heavy ORM investment you will not migrate |
| `@effect/ai` + one provider | Provider-swappable LLM apps ([AI intro](https://effect.website/docs/ai/introduction/))                                            | Single SDK call with no abstraction need  |
| `@effect/workflow`          | Durable multi-step processes (see engine integration in [Fault-tolerant ingestion](/knowledge-base/effect-ts/fault-tolerant-ingestion/))            | In-memory sub-second tasks                |
| `@effect/rpc`               | Typed TS↔TS RPC ([rpc README](https://github.com/Effect-TS/effect/blob/main/packages/rpc/README.md))                              | Cross-language interop (gRPC/OpenAPI)     |
| `@effect/cluster`           | Sharded entities, runners (see sharding concepts in [Fault-tolerant ingestion](/knowledge-base/effect-ts/fault-tolerant-ingestion/))               | Single-node apps |

## Experimental

`@effect/experimental`: staging modules with no stability guarantee ([`experimental` package.json](https://github.com/Effect-TS/effect/blob/main/packages/experimental/package.json)). Pin versions if you adopt in production.

## AI providers

Install `@effect/ai` plus one of: `@effect/ai-openai`, `@effect/ai-anthropic`, `@effect/ai-google`, `@effect/ai-amazon-bedrock`, `@effect/ai-openrouter` ([`packages/ai` tree](https://github.com/Effect-TS/effect/tree/main/packages/ai)).

## Dependency sketch

```
effect (core)
   ├── @effect/platform → platform-node | -bun | -browser
   ├── @effect/sql + driver
   ├── @effect/ai + provider
   ├── @effect/rpc
   ├── @effect/cluster → @effect/workflow
   ├── @effect/opentelemetry
   └── @effect/vitest
```

Arrows mean "typically composed with", not strict npm trees. `@effect/workflow` README composes `ClusterWorkflowEngine` with `PgClient.layer` from `@effect/sql-pg`.

<Aside type="note" title="Composition ≠ packaging">

[[effect-ts/composition|pipe / gen / fn]] apply regardless of package. Packaging only decides what you `npm install`.

</Aside>
