> Retry a failing effect with `Effect.retry` and a `Schedule`: a value that decides whether to recur and how long to wait between attempts.

<Steps>

1. **Retry** with `{ times: n }` or a `Schedule`.
2. **Backoff** with `Schedule.exponential`: always cap it.
3. **Bound** with `Schedule.intersect(..., Schedule.recurs(n))`.
4. **Jitter** with `Schedule.jittered` when many clients retry together.
5. **Filter** with `while` / `until` on the error tag.
6. **Fallback** with `Effect.retryOrElse` when the policy exhausts.

</Steps>

## Before you start

Install the core `effect` package before trying the retry examples. After the command finishes, confirm `package.json` contains `effect`; `Effect`, `Schedule`, and `Console` all come from that one package ([`Schedule.ts`](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/Schedule.ts), [`Effect.retry` L4399+](https://github.com/Effect-TS/effect/blob/main/packages/effect/src/Effect.ts#L4399-L4410)).

```bash
bun add effect
```

## 1. Retry N times

```ts twoslash
import { Effect } from "effect";

let count = 0;
const flaky = Effect.try({
  try: () => {
    count++;
    if (count < 4) throw new Error(`attempt ${count} failed`);
    return `ok on attempt ${count}`;
  },
  catch: (e) => e as Error,
});

const program = Effect.retry(flaky, { times: 3 });

console.log(Effect.runSync(program));
// ok on attempt 4
```

Here is the step-by-step visual execution trace of the synchronous runtime execution:

```text
[22:50:00.000] ▶️ [Sync Execution] Starting flaky program...
[22:50:00.001] 💥 Attempt #1 starting... count = 1
[22:50:00.002] ⚠️ Attempt #1 failed with: "attempt 1 failed" (retrying...)
[22:50:00.003] 💥 Attempt #2 starting... count = 2
[22:50:00.004] ⚠️ Attempt #2 failed with: "attempt 2 failed" (retrying...)
[22:50:00.005] 💥 Attempt #3 starting... count = 3
[22:50:00.006] ⚠️ Attempt #3 failed with: "attempt 3 failed" (retrying...)
[22:50:00.007] 💥 Attempt #4 starting... count = 4
[22:50:00.008] ✅ Attempt #4 succeeded! Returning "ok on attempt 4"
[22:50:00.009] 💾 Output: "ok on attempt 4"
```

`{ times: 3 }` means three **extra** attempts after the first (four tries total) ([retrying docs](https://effect.website/docs/error-management/retrying/#retry)).

## 2. Exponential backoff (cap it)

```ts twoslash
import { Effect, Schedule } from "effect";

let attempts = 0;
const flaky = Effect.sync(() => {
  attempts++;
  return attempts;
}).pipe(
  Effect.flatMap((n) =>
    n < 4 ? Effect.fail(new Error(`fail ${n}`)) : Effect.succeed(n),
  ),
);

const policy = Schedule.intersect(
  Schedule.exponential("10 millis"),
  Schedule.recurs(5),
);

const program = flaky.pipe(Effect.retry(policy));

attempts = 0;
Effect.runPromise(program).then((n) => console.log(`succeeded after ${n} attempts`));
```

Here is the step-by-step visual execution trace illustrating the exponential backoff timeline delays:

```text
[22:50:00.000] ▶️ [Promise Execution] Starting backoff program...
[22:50:00.001] 💥 Attempt #1 failed with: "fail 1"
[22:50:00.002] ⏳ Schedule: Delaying for 10ms (exponential backoff)
[22:50:00.013] 💥 Attempt #2 failed with: "fail 2"
[22:50:00.014] ⏳ Schedule: Delaying for 20ms (exponential backoff factor = 2)
[22:50:00.035] 💥 Attempt #3 failed with: "fail 3"
[22:50:00.036] ⏳ Schedule: Delaying for 40ms (exponential backoff factor = 2)
[22:50:00.077] 🎉 Attempt #4 succeeded! Value = 4
[22:50:00.078] 💾 Output: "succeeded after 4 attempts"
```

`Schedule.exponential` alone recurs **forever** ([built-in schedules](https://effect.website/docs/scheduling/built-in-schedules/#exponential)). Always intersect with `Schedule.recurs(n)` or use `times` / `until`. If you do not limit it, the retry loop continues infinitely with ever-growing delays:

```text
[22:50:00.000] Attempt #1 failed. Delaying 10ms...
[22:50:00.010] Attempt #2 failed. Delaying 20ms...
[22:50:00.030] Attempt #3 failed. Delaying 40ms...
[22:50:00.070] Attempt #4 failed. Delaying 80ms...
...
[22:55:00.000] Attempt #15 failed. Delaying 163.84s... (Loops forever!)
```

## 3. Jitter

```ts twoslash
import { Schedule } from "effect";

const policy = Schedule.intersect(
  Schedule.jittered(Schedule.exponential("100 millis")),
  Schedule.recurs(5),
);
// Each delay is ~80%–120% of the nominal value.
```

```text
// Nominal delays: 100ms, 200ms, 400ms, 800ms, 1600ms
// Execution trace with jitter (randomized between 80% and 120% of nominal):
```

## 4. Retry only specific errors

```ts twoslash
import { Data, Effect } from "effect";

class TransientError extends Data.TaggedError("TransientError")<{}> {}
class FatalError extends Data.TaggedError("FatalError")<{}> {}

let n = 0;
const program = Effect.gen(function* () {
  n++;
  if (n === 1) return yield* Effect.fail(new TransientError());
  if (n === 2) return yield* Effect.fail(new FatalError());
  return "done";
}).pipe(
  Effect.retry({
    while: (err: TransientError | FatalError) => err._tag === "TransientError",
  }),
);

n = 0;
Effect.runPromiseExit(program).then((exit) => console.log(exit._tag));
// Failure — FatalError on attempt 2, not retried
```

Here is the step-by-step visual execution trace illustrating the conditional error filtering predicate:

```text
[22:50:00.000] ▶️ [Exit Execution] Starting predicate filter program...
[22:50:00.001] 💥 Attempt #1 failed with: TransientError
[22:50:00.002] 🔍 Predicate check: error tag matches "TransientError" (while = true). Retrying...
[22:50:00.003] 💥 Attempt #2 failed with: FatalError
[22:50:00.004] 🔍 Predicate check: error tag "FatalError" does NOT match "TransientError" (while = false).
[22:50:00.005] 🚫 Halting retry flow. Propagating fatal error upward.
[22:50:00.006] 💾 Output Exit Status: Failure
```

Pair with [[effect-ts/typed-errors|typed errors]] so `while` can discriminate on `_tag`.

## 5. Fallback when retries exhaust

```ts twoslash
import { Console, Effect, Schedule } from "effect";

const liveFetch = Effect.fail(new Error("upstream down"));
const cached = Effect.succeed({ id: "u_1", name: "Ada (cached)" });

const policy = Schedule.addDelay(Schedule.recurs(2), () => "50 millis");

const resilient = Effect.retryOrElse(liveFetch, policy, (err: Error) =>
  Console.log(`giving up on live: ${err.message}`).pipe(Effect.flatMap(() => cached)),
);

Effect.runPromise(resilient).then(console.log);
// giving up on live: upstream down
// { id: 'u_1', name: 'Ada (cached)' }
```

## Built-in schedules

<Tabs>
  <TabItem label="Schedules">
    | Schedule | Behavior |
    | --- | --- |
    | `Schedule.recurs(n)` | At most `n` extra recurrences ([docs](https://effect.website/docs/scheduling/built-in-schedules/#recurs)); [retry example](#1-retry-n-times) |
    | `Schedule.spaced(d)` | Fixed gap after each run ends |
    | `Schedule.fixed(d)` | Fixed wall-clock interval |
    | `Schedule.exponential(base, factor?)` | Delays grow `base * factor^n` (default factor 2); [backoff example](#2-exponential-backoff-cap-it) |
    | `Schedule.jittered(s)` | Randomize each interval to 80%–120%; [jitter example](#3-jitter) |
    | `Schedule.intersect(a, b)` | Continue while **both** continue; **longer** delay wins; [backoff example](#2-exponential-backoff-cap-it) |
    | `Schedule.union(a, b)` | Continue while **either** continues; **shorter** delay wins |
  </TabItem>
  <TabItem label="retry vs repeat">
    | Combinator | Triggers on |
    | --- | --- |
    | [Effect.retry](#1-retry-n-times) | **Failure** |
    | `Effect.repeat` | **Success** |

    Same `Schedule` machinery, opposite trigger. `repeat` polls until success; `retry` recovers from transient failure.

  </TabItem>
</Tabs>

**Workhorse policy** for HTTP/ingestion: `Schedule.intersect(Schedule.jittered(Schedule.exponential("200 millis")), Schedule.recurs(3))`. Chain with [[effect-ts/composition|pipe]] after `timeout` and before `forEach` in [[effect-ts/fault-tolerant-ingestion|fault-tolerant ingestion]].

<Aside type="caution" title="Do not retry non-idempotent effects">

`Effect.retry` re-runs the whole effect. POSTs, charges, and emails replay unless the operation is idempotent or split into read (retry) vs write (no retry).

</Aside>

<Aside type="note" title="intersect vs compose">

Use `intersect` to cap backoff (`exponential ∩ recurs(5)`). `Schedule.compose` feeds outputs into inputs: different semantics ([combinators](https://effect.website/docs/scheduling/schedule-combinators/)).

</Aside>
